# 同步任务交互设计细则

## 1. 设计目标

同步任务页面应像成熟数据集成产品，而不是普通表单堆叠页。用户进入页面后，应清楚知道当前在哪一步、需要补什么、补完后会生成什么。

核心体验关键词：

- 向导式
- 工作台化
- 资产列表化
- 左右对照
- 先预览后执行
- 当前页反馈

## 2. 整体布局

### 2.1 页面骨架

页面由以下区域组成：

同步任务模块由三类页面组成：

1. 同步任务列表：菜单默认入口，用于查找、筛选、运行和编辑历史任务。
2. 同步任务详情：用于查看任务健康状态、配置、运行历史和日志诊断。
3. 新建 / 编辑向导：用于创建或修改同步任务配置。

新建 / 编辑向导由以下区域组成：

1. 顶部轻量步骤条：展示 4 个步骤和当前进度，不再使用单独占大块空间的步骤卡片。
2. 主工作台：承载当前步骤主要操作。
3. 底部操作条：上一步、下一步、保存、保存并执行。
4. 全局配置预览入口：固定为单一入口，不在每一步重复展示。

### 2.2 视觉原则

- 不使用大段说明文案占据工作区。
- 不把所有配置塞进一个长表单。
- 当前步骤只展示当前必要操作。
- 可执行动作要明确，禁用动作要说明原因。
- 列表和详情页优先服务“运维和修复”，不要被新建向导的说明文案占据。

## 3. 同步任务列表

同步任务菜单默认进入列表页，而不是直接进入新建向导。列表页参考 Fivetran Connections、Airbyte Connections 和 AWS Glue Jobs 的信息密度：用户首先要看到任务是否健康、最后一次跑得怎么样、失败后从哪里修。

### 3.1 列表布局

推荐布局：

```text
标题区：同步任务 / 新建同步任务

统计条：全部  运行中  失败  已调度  未调度

筛选区：搜索任务/源表/目标表 | 项目 | 状态 | 调度 | 源类型 | 目标类型

任务表格：
任务名称 | 项目 | 源端 | 目标端 | 状态 | 调度 | 最近运行 | 读/写行数 | 更新时间 | 操作
```

表格列优先级：

1. 任务名称：可点击进入详情。
2. 源端：数据源类型、库表路径。
3. 目标端：数据源类型、库表路径。
4. 状态：运行中、成功、失败、草稿、下线。
5. 调度：已启用、未启用、下次运行时间。
6. 最近运行：实例状态、时间、耗时。
7. 读 / 写行数：帮助判断是否真的同步了数据。
8. 操作：查看详情、编辑、运行一次、调度、复制、更多。

### 3.2 列表交互

- 点击 `新建同步任务`：进入四步新建向导。
- 点击任务名称：进入同步任务详情。
- 点击 `查看详情`：进入同步任务详情。
- 点击 `编辑`：进入四步编辑向导，并回填该任务配置。
- 点击 `运行一次`：弹出二次确认，确认后保存当前已发布配置并启动一次实例。
- 点击 `调度`：打开同步任务专用调度弹框。
- 点击 `复制`：基于当前任务复制一份草稿，进入编辑向导。
- 点击 `下线`：下线对应 Dolphin 工作流或调度，并把同步任务状态标为下线。
- 点击 `删除`：二次确认；删除同步任务元数据前提示是否同时处理 Dolphin 工作流定义。

失败任务的行内展示：

- 状态列使用红色失败标识。
- 最近运行列展示失败实例 ID、失败时间和短错误摘要。
- 操作区主动作优先显示 `编辑并修复`。

运行中任务的行内展示：

- 状态列展示运行中。
- 最近运行列展示实例 ID、开始时间和当前耗时。
- 操作区允许查看详情和查看实例，不允许静默覆盖配置。

### 3.3 空状态

当没有同步任务时，不展示大段营销式说明。空状态只保留：

- 标题：暂无同步任务
- 简短说明：新建一个同步任务后，可在这里查看运行状态和历史配置
- 主按钮：新建同步任务

## 4. 同步任务详情

详情页用于“判断、排障、回到编辑”。它不是重新做一套工作流详情页，而是把同步任务用户最关心的源目标、配置、运行历史和日志入口聚合起来。

### 4.1 详情布局

推荐布局：

```text
顶部摘要：
任务名称 / 状态 / 源端 -> 目标端 / 最近运行 / 调度状态
操作：编辑配置、运行一次、配置调度、查看工作流、查看最近实例

标签页：
概览 | 配置 | 运行历史 | 日志诊断 | 变更记录
```

### 4.2 概览标签

概览展示：

- 当前状态
- 最近实例 ID
- 最近运行结果
- 开始时间、结束时间、耗时
- 读行数、写行数
- 调度状态和下次运行时间
- 失败摘要

失败时，概览页顶部展示诊断条：

```text
最近一次运行失败：目标字段 ajbh 类型不兼容
操作：查看日志 / 编辑并修复 / 重新运行
```

### 4.3 配置标签

配置标签按同步任务心智分块：

- 源端：数据源、库、表、过滤条件。
- 目标端：数据源、库、Schema、表。
- 字段映射：自动映射数量、手动映射数量、未映射字段数量。
- 数据去向：同步前 SQL（custom_sql）。
- SeaTunnel 配置摘要：只展示关键配置和入口，不默认展开大段配置。

配置标签里的 `编辑配置` 按钮进入四步编辑向导。

### 4.4 运行历史标签

运行历史表格列：

- 实例 ID
- 状态
- 运行类型：手动运行 / 调度运行
- 开始时间
- 结束时间
- 耗时
- 读行数
- 写行数
- 操作：查看日志、查看 Dolphin 实例

点击实例 ID 进入 Dolphin 原生工作流实例详情，或在同步任务内打开日志诊断。

### 4.5 日志诊断标签

日志诊断优先服务失败定位：

- 默认展示最近失败实例。
- 展示失败阶段：保存、建表、启动、运行、写入。
- 展示错误摘要。
- 提供日志入口和 Dolphin 实例链接。
- 提供 `编辑并修复` 主按钮。

日志不可读时，展示不可读原因，不展示空白页。

### 4.6 变更记录标签

记录以下事件：

- 创建任务
- 保存草稿
- 发布配置
- 修改调度
- 手动运行
- 下线任务
- 删除任务

变更记录展示操作人、时间和摘要，不要求本期做字段级 diff。

## 5. 编辑历史任务

### 5.1 进入编辑

编辑入口来自：

- 同步任务列表的 `编辑`
- 同步任务详情的 `编辑配置`
- 失败诊断条的 `编辑并修复`

进入编辑后仍使用四步向导，但顶部标题区要明确当前模式：

- 新建模式：新建同步任务
- 编辑模式：编辑同步任务 / 任务名称
- 修复模式：编辑并修复 / 最近失败实例 ID

### 5.2 编辑回填

编辑向导必须回填：

- 项目
- 任务名称
- 源数据源、源库、源表
- 目标数据源、目标库、Schema、目标表
- 字段选择
- 字段映射关系
- 源端过滤条件
- 数据去向 custom_sql
- 目标 DDL 或目标表状态
- SeaTunnel 配置编辑状态
- 调度配置摘要

编辑向导不允许降级成只读摘要页或只展示字段映射摘要。进入编辑后必须继续使用原同步任务四步向导结构，尤其第 2 步必须保留“配置同步方案”工作台：

- 字段映射关系：继续使用已确认的 V4 双栏字段映射工作台风格，包含源字段区、目标字段设计区、连线、虚线/实线图例、主键/可空复选框、目标字段输入框和目标类型下拉框。
- 源端过滤条件：保留结构化条件行，支持字段、操作符和值，不退化成纯文本摘要。
- 数据去向：保留同步前 SQL（custom_sql）编辑区和 SeaTunnel 参数说明。
- 数据处理：保留“暂未实现”占位模块，不参与保存、执行或配置生成。

如果源表或目标表结构发生变化，页面应展示结构漂移提示：

- 源字段新增
- 源字段缺失
- 目标字段缺失
- 类型变化
- 映射失效

### 5.3 运行中编辑

运行中任务进入编辑时：

- 页面顶部展示提示：当前任务正在运行，本次修改会保存为待发布版本，不影响当前实例。
- `保存草稿` 可用。
- `保存并发布` 需要二次确认。
- 不允许静默覆盖正在运行的工作流配置。

### 5.4 保存编辑结果

编辑模式的保存动作：

- 保存草稿：更新同步任务元数据，不更新 Dolphin 工作流定义。
- 保存并发布：更新同步任务元数据，更新 Dolphin 工作流定义。
- 保存并执行：发布后立即启动一次实例。

保存完成后，页面建议回到详情页，而不是停在向导末尾。详情页顶部展示“已发布 / 已运行”的结果。

## 6. 第 1 步：选择源与目标

### 6.1 布局

采用已确认的源目标对照式工作台，不再使用普通纵向表单堆叠，也不使用大面积摘要卡：

| 区域 | 内容 |
|------|------|
| 顶部步骤条 | 1 选择源与目标 / 2 配置同步方案 / 3 执行与调度 / 4 预览与发布 |
| 基础信息区 | 配置检查、项目、任务名称、同步目标 |
| 工作台标题 | 选择同步对象；说明只确认源表和目标表 |
| 左侧源端卡片 | 数据源、数据库、数据表、连接状态 |
| 中间关系节点 | “对象确认”圆形节点和上下连接线 |
| 右侧目标端卡片 | 数据源、数据库、Schema、目标表名、目标表存在性提示 |

推荐布局：

```text
顶部：项目 / 任务名称 / 配置状态

┌──────────────────────┐   ┌──────────────┐   ┌──────────────────────┐
顶部：配置摘要 / 缺失项 / 下一步条件

┌──────────────────────┐       ┌──────────────────────┐
│ 源端 Source           │ 对象  │ 目标端 Target          │
│ 数据源 / 数据库 / 表   │ 确认  │ 数据源 / 数据库 / Schema│
│                       │       │ 目标表名 / 存在性提示   │
└──────────────────────┘       └──────────────────────┘
```

### 6.2 交互

- 选择源数据源后，清空源库、源表、字段。
- 选择源库后，清空源表、字段。
- 选择源表后，加载字段，并给目标表名提供默认建议。
- 选择目标数据源后，清空目标库、Schema、已有目标表。
- 数据源下拉展示 MySQL、PostgreSQL、Oracle、Doris 四类已支持类型，并在选项文案中明确类型。
- Oracle 选择库后，Schema 默认为连接用户名大写；Doris 选择库表时按 MySQL 协议展示库表，但目标端标签仍显示 Doris。
- 用户只填写目标表名，不再手动切换“新建目标表 / 使用已有表”。
- 目标表名变化后，系统自动做存在性检查：
  - 若目标表存在，提示“使用已有表”，第 2 步加载目标字段并按字段名自动匹配。
  - 若目标表不存在，提示“将新建目标表”，第 2 步按源字段生成目标字段。
- 数据源、数据库、表选择入口支持搜索。
- 第 1 步不展示字段总数、主键数、可空字段数、表注释、预估行数等摘要；这些信息进入第 2 步字段映射区承接。
- 不再展示“目标表策略”单独控件；目标表模式由“是否选择已有目标表”自动推导。
- 配置校验摘要放在第 1 步上方，实时更新，缺失项可点击定位到对应源端或目标端配置。
- 下一步按钮旁展示进入条件，例如“已加载 10 个字段，可进入字段设计”。
- 第 1 步只负责源端和目标端基础选择，不展示源端过滤条件、字段映射、数据去向或数据处理配置。
- 源端过滤条件进入第 2 步“配置同步方案”，避免把“连接选择”和“同步方案配置”混在一起。

### 6.3 文案

推荐短文案：

- 请选择项目
- 请选择源数据源
- 请选择源数据库
- 请选择源表
- 请选择目标数据源
- 请输入目标表名

避免文案：

- “工作流归属当前项目”
- “请在这里完成所有配置”
- “下一步将基于当前配置进入后续流程”

## 7. 第 2 步：配置同步方案

> 当前确认总原型：`../prototype/source-filter-workbench.html`  
> 当前确认字段映射基线：`../prototype/field-mapping-workbench-v4.html`

第 2 步不再只是字段设计，而是同步方案工作台。页面左侧展示同步方案模块列表，右侧展示当前模块详情。

模块顺序固定为：

1. 字段映射关系
2. 源端过滤条件
3. 数据去向
4. 数据处理

左侧模块列表只展示模块名称、状态标签和必要说明，不展示“1 映射 / 2 过滤 / 3 去向 / 4 处理”等重复编号提示。

### 7.1 字段映射关系

> 当前确认原型：`../prototype/field-mapping-workbench-v4.html`  
> 原型标记：`V4 映射图例与源字段标签优化`

字段映射关系是第 2 步的默认选中模块，也是核心必配模块。

正式开发必须把 V4 字段映射工作台拆成 Dolphin 内部组件，不允许 iframe 嵌入原型页。

原型阶段若复用 V4 内容，只能复用字段映射工作台本体，不得带入 V4 原型里的执行步骤大卡片、摘要大卡片或外层说明区域。

#### 7.1.1 布局

采用“表格编辑为主，连线辅助”的左右双栏加中间映射轨道：

| 区域 | 作用 |
|------|------|
| 左侧源字段表格 | 展示可同步字段，支持勾选和异常聚焦 |
| 中间映射轨道 | 展示源字段到目标字段映射，支持双向拖拽 |
| 右侧目标字段表格 | 展示并编辑目标字段、目标类型、字段注释、主键、可空 |

字段编辑优先通过表格完成；连线主要用于查看映射关系和手工改绑，不承担大部分日常配置。

页面顶部使用轻量摘要条展示：

- 自动映射数量
- 手工映射数量
- 未映射目标字段数量
- 一源多目标数量

中间或顶部必须提供映射图例：

- 虚线：系统自动映射
- 实线：手动拖拽映射

#### 7.1.2 源字段行

每行信息优先级：

1. 同步复选框
2. 源字段
3. 源类型
4. 字段注释
5. 连线锚点

左侧列顺序固定为：

1. 同步
2. 源字段
3. 源类型
4. 字段注释

左侧工具按钮只保留：

- 全选
- 反选
- 清空
- 只看异常

左侧工具按钮必须位于源字段区内部，不能散落到页面顶部或目标字段区。

源字段名后方内联展示状态标签：

- 主键
- 非空
- 可空

这些标签必须和源字段名在同一行，不能放在字段名下方，避免字段行高度被撑大。

字段注释过长时使用单行省略，hover 展示完整文本。

状态规则：

- 自动：该源字段当前至少存在一条自动映射关系
- 手工：该源字段当前至少存在一条手工映射关系
- 未参与：当前没有任何目标字段引用它
- 映射到 N 个目标：用于显示一源多目标

注释过长时使用单行省略，hover 展示完整文本。

#### 7.1.3 目标字段行

每行信息优先级：

1. 目标字段
2. 目标类型
3. 字段注释
4. 主键
5. 可空

目标字段区不需要全选、反选、清空按钮，因为它不是选择列表，而是字段设计表。

目标字段区顶部只保留与目标字段设计有关的操作。新建目标表模式下，展示“目标字段名规则”：

- 保持源名
- 全小写
- 全大写

规则直接作用于“目标字段”这一列，不再单独增加“字段名”列。

目标字段编辑规则：

- “目标字段”使用输入框，允许用户修改。
- “目标类型”使用下拉框，选项随目标数据库类型变化。
- “字段注释”使用输入框，允许用户修改。
- “主键”“可空”使用复选框，逐行可见。
- 不显示“来自 xx”“当前来源”“映射方式”等文本，因为来源和方式由连线和图例表达。
- 不显示重复的“字段名”列。

#### 7.1.4 拖拽连线

交互规则：

- 源字段可拖到目标字段。
- 目标字段可反向拖到源字段。
- 所有源字段和所有目标字段都必须有连接点，包括未映射字段。
- 字段行头部区域也可作为落点，不只依赖小圆点。
- 新连线建立后，如果目标字段已有来源，则替换旧来源。
- 一个源字段允许关联多个目标字段。
- 一个目标字段同一时刻只允许存在一个来源。
- 连线失败时不改变原映射。
- 默认直接展示自动映射和手工映射线，不再要求用户额外点“显示连线”。
- “只看异常”开启后，只保留异常字段和与异常相关的线。
- 表格滚动时，连线必须根据字段行真实 DOM 位置重新计算。

视觉规则：

- 连线 SVG 层放在左右字段面板之上的独立绝对定位层，不能被字段面板裁切。
- 源字段锚点放在左侧表格右外侧，目标字段锚点放在右侧表格左外侧。
- 左右锚点样式必须一致，以源字段锚点样式为准。
- 左右字段行高度保持一致，锚点处于字段行垂直中心。
- 系统自动映射使用虚线。
- 用户手动拖拽映射使用实线。
- 线条颜色克制，不使用高饱和大面积色。
- 当前拖拽中的线可以高亮。
- 锚点不要太突兀，靠近字段边缘。

双向拖拽建立映射前必须做字段类型兼容校验：

- 只有当目标字段类型能安全承接源字段类型时，才允许建立连线。
- 不兼容时，不建立连线、不改变原映射，并给出明确提示。
- 应尽量在拖拽过程中前置提示：可兼容目标字段高亮，不兼容目标字段置灰。

兼容原则采用“安全扩容”判断，例如：

- `INT -> BIGINT` 允许，`BIGINT -> INT` 不允许
- `VARCHAR(64) -> VARCHAR(255)` 允许，`VARCHAR(255) -> VARCHAR(64)` 不允许
- `DATE -> TIMESTAMP` 允许，`TIMESTAMP -> DATE` 默认不允许
- `DECIMAL(10,2) -> DECIMAL(18,4)` 允许，反向不允许

#### 4.1.5 自动映射

默认规则：

1. 新建目标表：目标字段由源字段生成，源字段名等于目标字段名，源类型按目标数据库类型映射，注释、主键、可空默认继承。
2. 已有目标表：目标字段由真实目标表字段生成，系统按字段名自动匹配源字段和目标字段。
3. 已有目标表中能匹配的字段默认勾选并建立映射。
4. 已有目标表中不能匹配的字段保留在右侧并标记“未映射”，用户手动判断是否连到某个源字段。
5. 已有目标表场景不鼓励编辑目标字段名和类型，页面应以真实目标表结构为准。
6. 已有目标表场景下，左侧保留全部源字段；没有自动命中的源字段默认不勾选、无连线、状态为“未参与”。
7. “全选”不会给未匹配字段强行按顺序补线；它只激活已有自动映射关系和已有手工映射关系。
8. “反选”只反转已有映射关系的参与状态，不自动创造新的字段关系。
9. “清空”只清空参与同步状态，不直接删除手工映射定义；再次全选时，原自动映射和手工映射可恢复参与。
10. “只看异常”时，左侧只看未连接任何目标字段的源字段，右侧只看 `未映射` 的目标字段。

新建目标表模式下，右侧顶部提供“目标字段名规则”切换：

- 保持源字段名
- 全小写
- 全大写

规则说明：

- 默认使用“保持源字段名”
- 仅对自动生成的目标字段名生效
- 用户若手工修改过某个目标字段名，该字段不应在批量切换大小写时被强制覆盖
- 已有目标表模式下，不展示该切换，字段名以真实目标表为准

目标类型映射规则：

- MySQL：优先使用 `BIGINT`、`INT`、`DECIMAL`、`DOUBLE`、`VARCHAR(255)`、`TEXT`、`DATETIME`、`JSON`。
- PostgreSQL：优先使用 `BIGINT`、`INTEGER`、`NUMERIC`、`DOUBLE PRECISION`、`VARCHAR(255)`、`TEXT`、`TIMESTAMP`、`JSONB`。
- Oracle：优先使用 `NUMBER(19)`、`NUMBER(10)`、`NUMBER(10,2)`、`BINARY_DOUBLE`、`VARCHAR2(255)`、`CLOB`、`DATE`、`TIMESTAMP`。
- Doris：优先使用 `BIGINT`、`INT`、`DECIMAL(10,2)`、`DOUBLE`、`VARCHAR(255)`、`STRING`、`DATE`、`DATETIME`。

用户手工修改后：

- 不因再次进入步骤而丢失。
- 若取消源字段勾选，相关目标字段和映射应移除或标记失效。
- 支持按名称自动映射、按顺序映射、清除映射、只看异常映射。

### 7.2 源端过滤条件

源端过滤条件是第 2 步里的可选模块，不在第 1 步展示。

布局：

- 模块顶部展示“可配置”状态。
- 条件区使用结构化行，不使用自由 SQL 文本框作为主入口。
- 每条条件一行展示：启用状态、字段、操作符、值、复制、删除。
- 右侧或下方展示 Source Query 预览，帮助用户理解 WHERE 拼接结果。

交互：

- 添加条件默认生成启用状态。
- 字段变化后，操作符选项根据字段类型变化。
- 文本字段支持等于、不等于、包含、前缀匹配、IN、为空、不为空。
- 数值字段支持等于、不等于、大于、小于、大于等于、小于等于、IN。
- 时间字段支持等于、大于、小于、大于等于、小于等于、区间。
- 多条条件默认 `AND` 拼接。
- 条件上限建议为 3 条，超过时提示用户收敛条件。
- 点击预估影响行数时，本期原型可模拟，真实开发需要后端接口支持时另行拆分。
- 删除全部条件后表示全量读取。

禁止行为：

- 不允许把正式同步过滤设计成用户必须手写整段 SQL。
- 不把“同步前 N 条”混入正式过滤条件；如果后续需要，作为试跑抽样能力单独设计。

### 7.3 数据去向

数据去向是第 2 步里的可选模块，用于配置目标端写入前动作。

当前版本只保留同步前 SQL：

- 页面名称：同步前 SQL（custom_sql）
- SeaTunnel 参数口径：`data_save_mode = CUSTOM_PROCESSING` + `custom_sql`
- 页面不提供“写入策略”配置入口。
- 页面不使用 `preSql` 命名，避免误导用户以为 SeaTunnel JDBC sink 存在 `preSql` 参数。

交互：

- 用户填写 SQL 后，在配置预览中展示对应 SeaTunnel sink 配置。
- 若当前 SeaTunnel sink 配置使用 `query` 模式且会导致 `custom_sql` 不执行，页面必须提示冲突，不能静默生成无效配置。
- 未填写同步前 SQL 时，SeaTunnel 配置不生成 `data_save_mode = CUSTOM_PROCESSING` 和 `custom_sql`。

### 7.4 数据处理

数据处理是第 2 步里的预留模块，本期不实现。

交互要求：

- 左侧模块列表展示“暂未实现”标签。
- 右侧模块详情只说明能力预留，不提供可编辑配置。
- 字符串替换、AI 辅助处理、数据向量化等入口本期禁用或不展示。
- 本期保存、执行、配置预览都不能读取该模块配置。

## 8. 第 3 步：执行与调度

### 8.1 建表交互

标准顺序：

1. 进入第 3 步后自动调用 DDL 预览接口。
2. 页面展示 SQL 编辑器加载态。
3. DDL 生成成功后，以 SQL 高亮编辑器展示。
3. 用户检查或编辑 DDL。
4. 点击确认建表。
5. 页面展示建表结果。

SQL 编辑器要求：

- 支持 SQL 语法高亮。
- 支持行号。
- 支持复制 SQL。
- 支持格式化。
- 支持重新生成。
- 支持编辑 / 只读状态。
- 格式化后的 `CREATE TABLE` 必须采用一行一个字段 / 约束的展示方式，字段缩进保持一致，不能把 `DECIMAL(10,2)`、`NUMBER(10,2)` 等类型内部逗号错误拆行。
- 用户编辑后展示“已手工修改”状态。
- 重新生成会覆盖已手工修改内容时，必须二次确认。

方言规则：

- Oracle 建表前通过元数据判断是否存在，不生成 `IF NOT EXISTS`；字段注释生成独立 `COMMENT ON COLUMN`。
- Doris 建表 SQL 默认追加 `DISTRIBUTED BY HASH(...) BUCKETS 1 PROPERTIES ("replication_num" = "1")`，确保单机 Docker 环境可执行。

禁止行为：

- 进入第 3 步自动建表。
- 选择字段后静默建表。
- 仍要求用户点击“生成建表语句”才能看到 DDL。
- 建表失败只提示“连接失败”。

允许行为：

- 进入第 3 步自动生成 DDL。
- 用户必须点击“确认建表”后才真正执行建表。

### 8.2 执行方式

执行方式包括：

- 立即执行
- 周期调度

立即执行强调“一次性运行”；周期调度强调“保存并启用定时”。

### 8.3 周期调度

交互参考 DolphinScheduler 原生定时弹框：

- 支持开始时间、结束时间。
- 支持周期类型。
- 支持生成 cron 或调度表达式。
- 不要求用户直接手写复杂表达式作为唯一入口。

周期调度配置入口不应被字段映射是否完成完全拦死，但真正保存调度前要校验必要配置。

## 9. 第 4 步：预览与发布

### 9.1 配置预览

配置预览采用全局浮层：

- 展示 SeaTunnel 配置。
- 支持编辑。
- 支持重置。
- 展示当前配置来源：系统生成 / 已手工编辑。
- 展示源端过滤条件在配置中的最终落点，便于用户确认同步范围。

### 9.2 保存同步任务

用户点击“保存同步任务”后：

1. 校验项目、源端、目标端、字段、映射。
2. 查询同名工作流。
3. 创建或更新工作流定义。
4. 页面显示保存成功和工作流编码。

### 9.3 保存并执行

用户点击“保存并执行”后：

1. 保存工作流。
2. 上线工作流。
3. 启动工作流实例。
4. 写入或更新同步任务列表资产。
5. 返回同步任务列表。
6. 列表展示最近运行状态，并允许进入详情或编辑修复。

不应强制跳转到 DolphinScheduler 原生实例详情页；第 4 步提交成功后应回到同步任务列表，和成熟数据集成产品的 connection / job 列表管理闭环一致。

### 9.4 运行结果区

建议字段：

| 字段 | 说明 |
|------|------|
| 当前阶段 | 保存中、上线中、启动中、运行中、成功、失败 |
| 工作流编码 | 用于追踪工作流定义 |
| 实例 ID | 用于追踪运行实例 |
| 实例状态 | 成功、失败、运行中 |
| 节点状态 | SeaTunnel 节点执行状态 |
| 执行机器 | 排查运行环境 |
| 同步数据量 | 真实写入行数 |

## 10. 错误状态设计

| 场景 | 推荐提示 |
|------|----------|
| 未选择项目 | 请选择归属项目 |
| 未选择源表 | 请选择源数据库和源表 |
| 未选择目标库 | 请选择目标数据库 |
| 目标表名为空 | 请输入目标表名 |
| 未选择字段 | 请至少选择一个同步字段 |
| DDL 生成失败 | 当前字段定义无法生成建表语句，请检查字段类型 |
| 目标表已存在 | 目标表已存在，已跳过重复建表 |
| 工作流保存失败 | 同步任务保存失败，请检查项目和任务配置 |
| 实例启动失败 | 工作流已保存，但启动实例失败，请到实例页查看原因 |

## 11. 页面维护检查表

每次修改同步任务页面前，至少检查：

1. 是否改变了四步向导的步骤边界。
2. 是否影响字段映射状态。
3. 是否影响 DDL 生成。
4. 是否影响 SeaTunnel 配置生成。
5. 是否影响工作流保存和执行。
6. 是否影响原生工作流定时功能。
