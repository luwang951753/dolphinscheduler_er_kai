# 变更记录

## 2026-05-19 同步任务 Agent MVP 设计与开发

- 背景：
  - 用户希望非专业人员不再手工配置数据源、目标表、字段映射和执行参数，而是通过自然语言描述同步需求，由 Agent 自动配置并执行同步任务。
  - 用户允许夜间自主推进，明天需要看到一版可体验的“Agent 接收命令 -> 语义理解 -> 自动配置 -> 执行同步任务”的工作流。
- 产品决策：
  - 第一版 Agent 不依赖外部大模型和 Milvus，使用本地确定性解析器，确保公司内网和离线环境可用。
  - Agent 不做独立任务模型，直接复用现有同步任务向导状态、字段映射 V4、保存工作流和执行工作流链路。
  - Milvus 作为二期能力，用于元数据语义召回、字段注释理解和历史任务推荐。
- 文档：
  - 新增 `sync-task/agent/req.md`：定义同步任务 Agent 的背景、目标、MVP 范围、解析规则和风险提示。
  - 新增 `sync-task/agent/prd.md`：定义 Agent 页面入口、抽屉结构、用户流程和验收标准。
  - 新增 `sync-task/agent/test-cases.md`：定义 Agent 打开、解析、套用到向导、确认执行和回归测试用例。
  - 新增 `sync-task/agent/implementation-plan.md`：记录开发实施计划。
- 实现：
  - `/sync-task` 列表页新增 `Agent 创建同步任务` 入口。
  - 新增同步任务 Agent 抽屉，支持命令输入、示例命令、执行阶段、方案卡片、风险提示、套用到向导和确认并执行。
  - 新增本地确定性解析器，支持 MySQL / PostgreSQL / Oracle / Doris 类型识别、`库.表` 路径识别、`LIMIT N` / `只同步 N 条` 抽样识别和“立即执行”意图识别。
  - Agent 复用现有项目、数据源、库表、字段加载、字段映射 V4、SeaTunnel 配置生成、保存工作流和执行工作流链路。
  - Agent 抽样限制写入 SeaTunnel source query，生成 `LIMIT N` 或 Oracle `FETCH FIRST N ROWS ONLY`。
- 验证：
  - `vue-tsc --noEmit` 通过。
  - `node tmp_sync_task_agent_qa.js` 通过，覆盖 Agent 解析、套用向导、字段映射和 `LIMIT 5` 配置预览。
  - `node tmp_sync_task_agent_execute_qa.js` 通过，覆盖 Agent 确认并执行、保存工作流、上线、启动实例和返回列表。
  - 测试报告：`sync-task/agent/test-report-2026-05-19.md`。

## 2026-05-16 同步任务列表删除历史动作并修复编辑回填

- 背景：
  - 用户反馈列表最右侧“历史”动作与“详情”重复，不清楚存在意义。
  - 用户反馈从真实列表点击“编辑”后，字段映射关系没有源字段区和目标字段区内容。
  - 用户继续验证发现“编辑”中的源端过滤条件没有回显，并怀疑数据去向的同步前 SQL 也没有回显。
- 根因确认：
  - “历史”只是直接打开详情抽屉的运行历史页签，和“详情”入口能力重复。
  - 真实列表资产从 Dolphin 工作流定义反查时，只设置了名称、实例和状态，`fieldRows/sourceColumns/targetColumns` 为空，导致编辑向导无法展示字段映射工作台内容。
  - 真实工作流反查虽然读取了 SeaTunnel `rawScript`，但只反解析了字段映射；`sourceFilters` 和 `sinkCustomSql` 仍被构造成空值，导致第 2 步“源端过滤条件”和“数据去向”模块无法回显历史配置。
- 实现要求：
  - 删除列表行级“历史”动作，保留“详情”和“编辑 / 修复”。
  - 从 Dolphin 工作流详情 `taskDefinitionList.taskParams.rawScript` 反解析 source query、transform query、sink query、database/table。
  - 将反解析结果回填为字段映射行、源字段列和目标字段列，使编辑页第 2 步可以看到源字段区、目标字段区和映射关系。
  - 从 source query 的 `WHERE` 子句反解析为结构化源端过滤条件；能识别 `=、!=、>、<、>=、<=、LIKE、IN、BETWEEN、IS NULL、IS NOT NULL` 的历史配置。
  - 从 sink 配置中的 `custom_sql` 反解析为“数据去向”的同步前 SQL，编辑页和详情配置页必须显示同一份内容。

## 2026-05-16 修复列表与概览最近读写行数不一致

- 背景：
  - 用户发现同步任务列表的“读 / 写”和详情概览的“最近读 / 写”中读数显示为 `-`，但运行历史里“读 / 写”正常。
  - 根因确认：执行状态轮询只从 SeaTunnel 日志解析 `Total Write Count` 并写入 `writeRows`；`readRows` 一直为空。历史行又使用同一个写入数拼接 `5 / 5`，造成运行历史看似正常，而列表和概览读数不正确。
- 实现要求：
  - 从任务日志同时解析 `Total Read Count` 和 `Total Write Count`。
  - 列表、详情概览、运行历史必须使用同一组真实读写行数。
  - 如果只有写入数没有读取数，读取数不得伪造；但 SeaTunnel 日志存在读取数时必须展示。

## 2026-05-15 同步任务资产管理方案

- 背景：
  - 用户发现同步任务运行后缺少回到“同步任务”查看和编辑历史任务的入口。

  - AWS Glue Jobs：Jobs 列表支持运行、调度、查看最近运行和编辑。

  - `sync-task/product/prd.md` 新增“同步任务资产管理”，把同步任务列表、详情、编辑回填从后续候选提升为维护闭环能力。
  - `sync-task/product/interaction-design.md` 新增同步任务列表、同步任务详情、编辑历史任务的交互规则。

  - `同步任务` 菜单默认进入任务列表，不再直接进入新建向导。
  - 列表提供新建、搜索、筛选、状态、最近运行、读写行数和行级操作。

  - 不能只依赖 Dolphin 工作流定义反解析，需要保存同步任务结构化元数据，才能支撑列表、详情和编辑回填。

## 2026-05-14 SeaTunnel 手动字段映射 transform 规则固化

- 背景：
  - 用户实测发现：已有目标表场景下，手动连接源字段和目标字段后，生成的 SeaTunnel 配置仍不能正确表达 sink 写入字段关系，无法保证数据同步正确。
  - 之前仅在 source query 中生成别名，未显式生成 SeaTunnel transform 到 sink 的链路，测试覆盖不足。
- 文档更新：
  - `sync-task/core/req.md` 新增 `13.4 SeaTunnel 字段映射生成规则`，要求已有目标表手动映射必须生成 `source -> transform -> sink` 链路。
  - `sync-task/product/prd.md` 补充状态一致性原则：手动异名映射必须通过 `transform Sql` 生成目标字段名，sink 读取 transform 输出。
  - `sync-task/test/test-matrix.md` 新增 `TC-P2-014`，覆盖已有目标表手动映射生成 SeaTunnel transform。
  - `quality/e2e-click-testing/test-cases.md` 补充 `TC-P1-004` 的 transform 验收标准。
- 验收重点：
  - `source.Jdbc.result_table_name = "sync_source"`。
  - `transform.Sql.source_table_name = "sync_source"`。
  - `transform.Sql.result_table_name = "sync_mapped"`。
  - `transform.Sql.query` 按目标字段顺序生成 `源字段 as 目标字段`。
  - `sink.Jdbc.source_table_name = "sync_mapped"`。
