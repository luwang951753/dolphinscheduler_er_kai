# 数据预览表结构查看设计说明

日期：2026-05-20

## 背景

当前“数据预览”已经具备数据源、数据库、表对象树、数据网格、筛选、排序、关联、列设置和复制 SQL 能力，但缺少“查看表结构”。用户在排查同步结果、确认字段类型、判断主键/可空/索引时，需要离开 DolphinScheduler 去 Navicat、DataGrip、DBeaver 等工具查看结构，影响闭环效率。

本设计只覆盖产品原型阶段，正式 Dolphin 二开需在原型确认后再进入实现。

## 成熟产品参考

### Navicat

Navicat 的表设计能力围绕字段、索引、外键、触发器、选项等页签组织。字段是核心表格，包含字段名、类型、长度、可空、默认值、注释等信息。适合参考其“结构信息高密度表格”表达方式。

### DataGrip

DataGrip 将数据查看、DDL、表对象信息放在数据库对象上下文里，用户从对象树打开表后，可以在同一工作区查看数据、DDL 和结构。适合参考其“数据与结构平级切换”的工作台模式。

### DBeaver / CloudBeaver

DBeaver 的 Table Properties 通常包含 Columns、Constraints、Foreign Keys、Indexes、DDL、Data 等子页签。适合参考其“表详情内部多页签”的信息架构。

### pgAdmin

pgAdmin 在对象属性中展示 Columns、Constraints、Indexes 和 SQL/DDL。适合参考其“结构与 SQL 可审计”的方式。

### DataWorks / 数据地图

DataWorks 更偏数据资产视角，表详情强调字段信息、分区信息、血缘、预览、治理属性。适合参考其“表结构同时服务数据开发和治理排查”的思路，但本模块暂不做血缘和治理。

## 设计结论

表结构不应放在右侧列设置抽屉，也不应只是工具栏里的一个弹窗按钮。它应当作为当前表的主工作区视图，与“数据预览”平级。

当前原型采用四个工作区页签：

- 数据预览
- 表结构
- DDL
- 索引约束

这样符合 DataGrip / DBeaver 的成熟模式，也能避免重要功能被右侧浮层遮挡。

## 页面行为

### 入口

用户从左侧对象树点击某张表后，右侧工作区默认进入“数据预览”。在工作区工具条下方提供视图页签，用户可切换到“表结构”“DDL”“索引约束”。

### 表结构

表结构页应展示：

- 表名
- 表注释
- 数据源类型
- 存储引擎或表类型
- 估算行数
- 最近更新时间
- 字段清单

字段清单列：

- 序号
- 字段名
- 类型
- 长度 / 精度
- 主键
- 可空
- 默认值
- 索引
- 字段注释

交互能力：

- 搜索字段名、类型、注释
- 快捷过滤：全部、主键、非空、有索引、无注释
- 复制字段名
- 复制建表 SQL
- 切换表后刷新当前表结构

### DDL

DDL 页展示格式化 SQL，要求一行一个字段，支持复制。首期只做只读查看，不做在线编辑表结构。

### 索引约束

索引约束页展示索引列表、唯一性、字段、类型。外键或约束元数据为空时，需要给出明确空状态，不能让用户误以为加载失败。

## 不做范围

首期不做：

- 在线改表
- 新增字段、删除字段、修改字段类型
- 血缘分析
- 分区管理
- 触发器管理
- 权限授权
- 任意 SQL 编辑器

## 后续实现建议

后端新增结构化元数据接口，不能让前端拼任意 SQL：

- 查询表基础信息
- 查询字段元数据
- 查询索引信息
- 查询约束 / 外键信息
- 查询格式化 DDL

接口必须复用 DolphinScheduler 登录态和数据源权限校验。表名、库名、schema 名必须来自元数据白名单。

## 测试点

正式开发后至少覆盖：

- 从对象树点击表后可进入表结构页
- 表结构字段数量、字段名、类型、注释展示正确
- 主键、非空、索引状态展示正确
- 搜索字段名、类型、注释有效
- 快捷过滤全部、主键、非空、有索引、无注释有效
- DDL 一行一个字段并支持复制
- 索引约束页有索引时展示，约束为空时展示空状态
- 切换不同表后结构、DDL、索引同步刷新
- 无权限或元数据读取失败时显示可理解错误
- 原有数据预览、筛选、排序、列设置、关联能力不回归
