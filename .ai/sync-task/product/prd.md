# 同步任务产品 PRD

## 1. 产品定位

同步任务是 DolphinScheduler 二开模块，用于把“数据库表到数据库表”的同步配置从低层 SeaTunnel 配置，提升为可视化、可保存、可调度、可运行的 DolphinScheduler 工作流能力。

本模块面向数据开发、数据集成开发和调度平台管理员。它不是独立数据集成平台，也不是完整替代 DolphinScheduler 工作流编排，而是在 DolphinScheduler 现有体系内补齐“低代码配置同步任务”的入口。

## 2. 成熟产品参考

| 产品 | 借鉴点 | 不照搬点 |
|------|--------|----------|
| DataWorks 数据集成 | 向导式源端、目标端、字段映射、调度发布 | 不复制其复杂运维体系 |
| Azure Data Factory Copy | 源、目标、映射、触发器的清晰边界 | 不引入完整 Data Flow 画布 |
| Airbyte Connections | 连接、字段选择、同步状态反馈 | 不引入独立连接管理和插件市场 |
| Fivetran Schema 配置 | Schema / Table / Column 分层选择和字段启停 | 不引入完整连接监控与 ELT 运维体系 |
| Fivetran / Airbyte Connection 详情 | 列表进入连接详情，详情内查看状态、运行历史、日志和设置 | 不另建一套连接市场或外部账号体系 |
| AWS Glue Jobs | Jobs 列表支持查看、运行、调度、最近运行和编辑 | 不复制完整 ETL 脚本编辑和作业类型体系 |
| DataGrip / CodeMirror SQL 编辑器 | SQL 高亮、行号、复制、格式化、编辑状态 | 不把同步任务变成通用 SQL IDE |
| 云厂商数据集成产品 | 建表预览、运行状态、任务实例反馈 | 不做重型多租户数据开发平台 |

## 3. 用户与场景

### 3.1 主要用户

- 数据开发工程师：创建并维护常见表同步任务。
- 数据集成开发工程师：关注字段映射、目标表结构、同步结果。
- 平台管理员：关注二开功能是否破坏 DolphinScheduler 原生能力。

### 3.2 高频场景

1. 将 MySQL 表同步到 PostgreSQL。
2. 将 Oracle 表同步到 MySQL / PostgreSQL / Doris。
3. 将 MySQL / PostgreSQL 表同步到 Doris。
4. 基于源表字段快速生成目标表字段。
5. 只同步部分字段。
6. 目标字段名、类型、注释需要调整。
7. 保存为工作流，立即执行一次。
8. 配置周期调度，后续按周期运行。
9. 执行后查看实例状态和同步数据量。
10. 从同步任务列表找到历史任务，查看配置、运行历史和失败原因。
11. 任务失败后回到同步任务编辑页修正配置并重新发布。

## 4. 产品边界

### 4.1 当前版本做什么

- 单表同步配置。
- 源端和目标端复用 DolphinScheduler 数据源。
- 数据源类型支持 MySQL、PostgreSQL、Oracle、Doris；其中 Doris 按 MySQL 协议连接，但在 UI、DDL 和类型映射上作为独立目标类型展示。
- 字段元数据读取。
- 字段选择、目标字段设计、字段映射。
- 目标端建表 DDL 预览和执行。
- SeaTunnel 配置生成、预览和编辑。
- 保存为 DolphinScheduler 工作流。
- 已保存同步任务列表、详情和编辑入口。
- 同步任务运行历史摘要。
- 保存并执行。
- 周期调度配置。
- 执行提交成功后返回同步任务列表，并在列表中展示运行状态和同步数据量。

### 4.2 当前版本不做什么

- 不做独立数据同步平台。
- 不做多表批量同步。
- 不做复杂字段表达式转换。
- 不做增量同步全套策略。
- 不做数据质量校验和对账。
- 不重写 DolphinScheduler 原生工作流编辑器。

## 5. 信息架构

### 5.1 页面入口

- 菜单名称：同步任务
- 菜单位置：源中心右侧
- 当前代码路由：`/sync-task`
- 菜单进入后默认展示“同步任务列表”，不再直接进入新建向导。
- “新建同步任务”按钮进入四步新建向导。
- 点击任务名称或“查看详情”进入同步任务详情页。
- 点击“编辑”进入四步编辑向导，并回填该任务已保存的配置。
- 文档历史口径：`/ui/sync-task` 表示 DolphinScheduler UI 内的同步任务页面，后续开发以实际前端路由 `/sync-task` 为准。

### 5.2 页面结构

同步任务模块由三类页面组成：

| 页面 | 用户目标 | 关键能力 |
|------|----------|----------|
| 同步任务列表 | 找到、筛选、运行、编辑已有同步任务 | 搜索、筛选、状态、最近运行、行级操作 |
| 同步任务详情 | 判断任务是否健康、哪里失败、配置是什么 | 概览、配置、运行历史、日志诊断、变更记录 |
| 新建 / 编辑向导 | 创建或修改同步任务配置 | 四步向导、保存、执行、调度 |

新建 / 编辑向导仍保留 4 步：

| 步骤 | 名称 | 用户目标 | 系统输出 |
|------|------|----------|----------|
| 1 | 选择源与目标 | 确认项目、源表、目标表 | 源端和目标端上下文 |
| 2 | 配置同步方案 | 配置字段映射、源端过滤、数据去向和预留数据处理 | 字段定义、映射关系、过滤条件、写入前 SQL |
| 3 | 执行与调度 | 预览 DDL、确认建表、选择执行方式 | 目标表、执行策略 |
| 4 | 预览与发布 | 检查配置、保存、执行、看结果 | 工作流、实例、同步结果 |

## 6. 功能需求

### 6.0 同步任务资产管理

**用户目标**

让用户能像管理 DataWorks 同步节点、Fivetran / Airbyte connection、AWS Glue job 一样管理历史同步任务：快速知道哪些任务正常、哪些失败、最后一次同步了多少数据，并能从失败任务回到编辑页修复。

**列表功能要求**

- `同步任务` 菜单默认进入同步任务列表。
- 列表顶部提供主按钮：`新建同步任务`。
- 列表顶部提供搜索框，支持按任务名称、源表、目标表、工作流编码搜索。
- 列表提供筛选：项目、任务状态、最近运行结果、调度状态、源端类型、目标端类型。
- 列表提供轻量统计：全部、运行中、失败、已调度、未调度。
- 表格列至少包含：
  - 任务名称
  - 项目
  - 源端
  - 目标端
  - 任务状态
  - 调度状态
  - 最近运行
  - 最近读 / 写行数
  - 更新时间
  - 操作
- 行级操作至少包含：
  - 查看详情
  - 编辑
  - 运行一次
  - 调度
  - 复制
  - 更多：下线、删除
- 任务名称可点击进入详情页。
- 失败任务在列表中应突出失败原因摘要，并提供 `编辑并修复` 快捷动作。
- 运行中任务允许查看详情和实例，不允许静默覆盖线上配置。

**详情功能要求**

- 详情页顶部展示任务名称、当前状态、源端、目标端、最近运行、调度状态、工作流编码。
- 详情页提供主要动作：
  - 编辑配置
  - 运行一次
  - 配置调度
  - 查看 Dolphin 工作流
  - 查看最近实例
- 详情页使用标签页组织：
  - 概览：状态、最近运行、读写行数、耗时、失败摘要。
  - 配置：源端、目标端、字段映射、源端过滤条件、数据去向、SeaTunnel 配置摘要。
  - 运行历史：运行实例列表、状态、开始时间、结束时间、耗时、读写行数。
  - 日志诊断：最近一次实例下全部任务的原始运行日志、任务实例 ID、状态、错误摘要、全屏查看和 Dolphin 实例链接。
  - 变更记录：创建、编辑、发布、调度变更记录。
- 从详情页点击 `编辑配置` 时，进入四步编辑向导，并回填该同步任务的结构化配置。
- 从运行历史点击某次实例时，进入 Dolphin 原生实例详情或同步任务内日志诊断视图。

**编辑规则**

- 未运行或已结束任务：允许直接编辑，保存后更新同步任务配置和对应 Dolphin 工作流定义。
- 运行中任务：不允许直接覆盖当前运行实例；进入编辑时提示“当前任务正在运行，本次修改会保存为待发布版本”。
- 失败任务：编辑入口应带上失败上下文，例如最近失败实例、失败步骤和日志入口。
- 编辑后保存支持两种结果：
  - 保存草稿：仅保存同步任务配置，不影响线上调度。
  - 保存并发布：更新 Dolphin 工作流定义，影响下次运行或下一次调度。
- 如果任务已配置周期调度，发布新版本后应明确提示调度会使用最新版本。

**数据要求**

- 同步任务列表不得使用固定静态样例数据，必须优先来自 Dolphin 真实工作流定义或同步任务元数据。
- 当前过渡阶段允许从 Dolphin 工作流定义、最近实例和调度信息反查列表数据。
- 同步任务不能长期只依赖 Dolphin 工作流定义反解析。
- 系统需要保存结构化同步任务元数据，用于列表、详情和编辑回填。
- 推荐新增同步任务元数据模型，至少包含：
  - 同步任务 ID
  - 项目编码
  - Dolphin 工作流定义编码
  - 任务名称
  - 源端配置 JSON
  - 目标端配置 JSON
  - 字段映射 JSON
  - 源端过滤条件 JSON
  - 数据去向 JSON
  - SeaTunnel 配置
  - 任务状态
  - 最近实例 ID
  - 最近运行状态
  - 最近读 / 写行数
  - 创建人、更新人、创建时间、更新时间

**异常处理**

- Dolphin 工作流定义被删除：列表展示“工作流缺失”，允许重新发布或删除同步任务元数据。
- 数据源被删除：详情页展示“数据源不可用”，编辑时要求重新选择数据源。
- 最近实例日志不可读：展示日志不可读原因，并保留 Dolphin 实例入口。
- 任务运行中编辑：必须明确提示版本影响，不允许静默覆盖。

### 6.1 选择源与目标

**用户目标**

快速确定同步任务从哪里读、写到哪里、归属哪个项目。

**功能要求**

- 归属项目必选。
- 支持任务名称，默认根据源数据源、源表、目标数据源、目标表自动生成，允许用户编辑。
- 源端选择数据源、数据库、表。
- 目标端选择数据源、数据库、Schema、目标表名。
- 数据源下拉只展示当前同步任务已支持的类型：MySQL、PostgreSQL、Oracle、Doris。
- Oracle 的“数据库”选择应使用连接配置中的服务名 / 默认 PDB 作为上下文，Schema 默认使用登录用户名的大写形式；Doris 的库列表、表列表按 MySQL 协议读取。
- 第 1 步采用源端 / 目标端左右对照工作台，中间展示同步链路摘要，而不是普通纵向表单堆叠。
- 源端和目标端卡片需要展示数据源类型、连接名称、当前选择路径和连接/加载状态。
- 数据源、数据库、表选择应支持搜索，避免长列表场景下只能滚动查找。
- 目标表可选。选择已有表时表示同步到已有表；不选择已有表、只填写目标表名时表示新建目标表。
- 选择源表后自动加载字段元数据。
- 选择源表后展示字段统计，例如字段数、主键数、可空字段数、字段加载状态。
- 目标表名默认可基于源表名给出建议。
- 不再暴露“目标表策略”三选一控件，避免用户理解成本过高：
  - 若用户选择了目标端已有表，系统按已有表字段作为目标字段。
  - 若用户没有选择目标端已有表，系统按目标表名新建表，并基于源字段生成目标字段草稿。
- 下一步前展示配置校验摘要，包括项目、源端连接、源表字段、目标端连接和目标表模式。
- 第 1 步不承载源端过滤条件、字段映射、数据处理或数据去向等同步方案配置；这些能力统一进入第 2 步“配置同步方案”。

**异常处理**

- 数据源不可用：提示检查数据源连接。
- 库列表加载失败：提示当前数据源不可读取库列表。
- 表列表为空：展示空状态，不阻塞选择其他库。
- 配置不完整时，校验摘要应指出缺失项，并允许点击定位到对应配置区域。

### 6.2 配置同步方案

**用户目标**

在源端和目标端已经确定后，完成真正影响同步行为的方案配置，包括字段如何映射、源端读取范围如何过滤、目标写入前是否执行 SQL，以及预留的数据处理能力。

**功能要求**

- 第 2 步名称固定为“配置同步方案”，不再叫“设计字段”。
- 第 2 步采用左侧同步方案模块列表 + 右侧模块详情的工作台布局。
- 顶部 4 步进度条保持轻量化，不再为步骤条单独占用大块卡片区域；后续真实 Dolphin 页面开发同步采用该风格。
- 左侧同步方案模块顺序固定为：
  1. 字段映射关系
  2. 源端过滤条件
  3. 数据去向
  4. 数据处理
- 左侧模块列表不展示“1 映射 / 2 过滤 / 3 去向 / 4 处理”等重复编号标签，只保留模块名称、状态标签和必要说明。
- 字段映射关系为核心必配模块。
- 源端过滤条件为可选模块。
- 数据去向为可选模块。
- 数据处理为预留模块，本期只保留入口和“暂未实现”状态，不进入真实开发。

#### 6.2.1 字段映射关系

- 第 2 步以已确认原型 `../prototype/field-mapping-workbench-v4.html` 为设计基线，正式开发必须与该原型保持布局和交互一致。
- 在 `../prototype/source-filter-workbench.html` 中展示字段映射时，不允许使用 iframe 嵌入 V4 整页；正式开发必须将 V4 字段映射工作台拆成 Dolphin 内部正常组件。
- 字段映射组件只包含 V4 的字段映射工作台本体，不包含 V4 原型里的执行步骤大卡片、摘要大卡片或其他外层说明区域。
- 源字段区列顺序固定为：同步、源字段、源类型、字段注释。
- 源字段区工具按钮只保留：全选、反选、清空、只看异常；这些按钮必须放在源字段区内部。
- 源字段名后方内联展示主键、非空、可空等轻量标签，不再放到字段名下一行，避免行高膨胀。
- 源字段注释单行展示，过长时省略，hover 或 tooltip 展示完整内容。
- 目标字段设计区列顺序固定为：目标字段、目标类型、字段注释、主键、可空。
- 目标字段使用输入框，允许用户直接修改字段名。
- 目标类型使用下拉选择，允许用户按目标端数据库类型选择合法类型。
- 字段注释使用输入框，允许用户编辑。
- 主键、可空使用复选框，必须逐行可见。
- 目标字段区不再展示重复的“字段名”列，因为“目标字段”已经承担字段名编辑能力。
- 目标字段区不展示“来自 xx”“当前来源”“映射方式”等冗余文案，来源关系通过连线表达。
- 新建目标表模式下，右侧顶部提供“目标字段名规则”：保持源名、全小写、全大写，规则直接作用于“目标字段”输入框。
- 目标字段名规则只自动改写未被用户手工编辑过的目标字段；用户手工修改过的字段名不能被批量规则覆盖。
- 源端过滤条件不会影响字段设计区的字段结构，但会影响字段预览和后续同步范围的配置预览。
- 目标字段按已选源字段自动生成。
- 目标字段支持编辑字段名、类型、注释、主键、可空。
- 目标表不存在 / 新建目标表场景：按当前方式基于源字段生成目标字段，并默认一对一映射。
- 目标表已存在场景：以目标表字段为准生成目标字段列表，系统按字段名自动映射可匹配字段；未匹配的目标字段保留在右侧并标记“未映射”，由用户判断是否手动连线或保留不参与。
- 已有目标表场景下，正式开发应以真实目标字段为准；若允许编辑字段名或类型，必须明确标识为“同步写入映射别名 / 类型转换建议”，不得让用户误以为已修改真实目标表结构。
- 目标字段类型下拉必须随目标数据源类型变化，分别展示 MySQL、PostgreSQL、Oracle、Doris 的常用类型。
- Oracle 类型映射需优先使用 `NUMBER`、`VARCHAR2`、`CLOB`、`DATE`、`TIMESTAMP`；Doris 类型映射需优先使用 `BIGINT`、`INT`、`DECIMAL`、`DOUBLE`、`VARCHAR`、`STRING`、`DATETIME`。
- 第 2 步以字段表格编辑为主，连线只作为映射关系辅助展示和手工改绑入口。
- 默认一对一映射。
- 支持左右双向拖拽连线改绑。
- 所有源字段和所有目标字段都必须有可见连接点，包括未映射字段，方便用户手动连线。
- 源字段连接点位于源字段区最右侧字段附近；目标字段连接点位于目标字段区左侧，左右样式必须一致。
- 字段映射变化后，连线立即更新。
- 支持按名称自动映射、按顺序映射、清除映射、只看异常映射。
- 连线默认展示，不再提供“显示 / 隐藏连线”按钮。
- 自动映射使用虚线；手动拖拽映射使用实线。
- 页面必须提供简洁图例说明：虚线表示系统自动映射，实线表示手动拖拽映射。
- 连线层必须独立于左右字段面板之上，不能被字段表格或容器裁切。
- 支持从源字段拖到目标字段，也支持从目标字段反向拖到源字段。
- 一个源字段可以映射到多个目标字段；一个目标字段同一时刻只能有一个来源。
- 目标字段已有来源时，新拖拽映射会替换旧来源。
- 建立连线前必须做字段类型兼容判断，只有目标字段类型能安全承接源字段类型时才允许关联。
- 不兼容时不建立连线、不改变原映射，并给出明确提示。

#### 6.2.2 源端过滤条件

- 源端过滤条件放在第 2 步“配置同步方案”中，不放在第 1 步“选择源与目标”。
- 源端过滤条件是可选模块，不配置时表示全量读取。
- 过滤条件的产品语义参考 DataWorks 的“配置同步方案 / 数据处理区域”和 Fivetran row filtering：按表配置、由系统拼接、用于控制同步范围，而不是把用户引导去写自由 SQL。
- 过滤条件支持字段、操作符、值的结构化输入，支持常见文本、数值、时间和布尔类型。
- 条件支持启用 / 禁用、删除、复制。
- 条件上限建议为 3 条，超过时提示用户收敛条件。
- 多条条件默认按 `AND` 拼接。
- 配置预览和 SeaTunnel source query 中必须展示源端过滤条件。
- “同步几条数据”不作为正式同步配置项；若要支持试跑，应单独作为预览抽样能力，不与正式同步参数混用。

#### 6.2.3 数据去向

- 数据去向放在第 2 步“配置同步方案”中，作为可选模块。
- 数据去向当前只保留同步前 SQL 能力，不提供“写入策略”配置入口。
- 同步前 SQL 使用 SeaTunnel JDBC sink 的 `custom_sql` 口径，不使用 `preSql` 命名。
- 当用户填写同步前 SQL 时，系统生成 SeaTunnel 配置时应同步生成 `data_save_mode = CUSTOM_PROCESSING` 和 `custom_sql`。
- 若使用 sink `query` 模式导致 `custom_sql` 不会执行，系统应禁止该组合或给出明确提示，不能生成看似配置成功但实际不执行的配置。
- 页面文案使用“同步前 SQL（custom_sql）”，避免用户误以为 SeaTunnel 原生存在 `preSql` 参数。

#### 6.2.4 数据处理

- 数据处理模块本期仅保留入口，用于承接后续字符串替换、AI 辅助处理、数据向量化等能力。
- 数据处理模块必须展示“暂未实现”标签。
- 数据处理模块内的输入控件本期应禁用或隐藏，不能让用户误以为已经可配置并可生效。
- 本期 SeaTunnel 配置生成、保存、执行不读取数据处理模块配置。

**异常处理**

- 未选择任何字段时不能进入真正执行链路。
- 目标字段名为空时提示补全。
- 重复目标字段名需要提示冲突。
- 字段映射断开或目标字段无来源时，应在异常筛选中可见。
- 字段类型不兼容时，应提示源字段类型、目标字段类型和不允许映射的原因。

### 6.3 执行与调度

**用户目标**

确认目标端表结构，并选择立即执行或周期调度。

**功能要求**

- 进入第 3 步后自动生成 DDL，不再要求用户手动点击“生成建表语句”。
- DDL 展示区域采用 SQL 编辑器样式，支持 SQL 高亮、行号、复制 SQL、格式化、重新生成和编辑状态标识。
- DDL 生成需要按目标端方言生成：
  - MySQL 使用反引号、列内 `COMMENT`、`CREATE TABLE IF NOT EXISTS`。
  - PostgreSQL 使用双引号、`COMMENT ON COLUMN`。
  - Oracle 使用双引号、`COMMENT ON COLUMN`，不使用 `IF NOT EXISTS`，建表前通过元数据判断是否已存在。
  - Doris 使用反引号、列内 `COMMENT`，追加 `DISTRIBUTED BY HASH(...) BUCKETS 1 PROPERTIES ("replication_num" = "1")`，便于本地单副本测试。
- DDL 生成期间显示加载态，生成失败时展示可理解错误原因。
- 用户编辑 DDL 后标记为“已手工修改”。
- 点击“重新生成”时，如果当前 DDL 已手工修改，需要二次确认是否覆盖。
- 点击确认建表后才执行 DDL。
- DDL 自动生成不等于自动建表，建表动作仍必须由用户确认。
- 表已存在时给出可理解提示。
- 立即执行必须触发保存、上线、启动实例。
- 周期调度参考 DolphinScheduler 原生定时配置体验。
- 建表状态应区分：未执行、建表中、成功、表已存在、失败。

**异常处理**

- DDL 生成失败：提示字段定义不完整或类型不支持。
- DDL 执行失败：展示后端返回原因。
- 调度保存失败：提示调度参数或工作流状态问题。

### 6.4 预览与发布

**用户目标**

发布前确认配置，保存任务或执行任务，并看到运行结果。

**功能要求**

- 全局单一配置预览入口。
- 支持查看、编辑、重置 SeaTunnel 配置。
- 保存同步任务创建或更新工作流定义。
- 保存并执行或启用调度成功后返回同步任务列表。
- 列表和详情展示实例 ID、实例状态、最近运行时间、同步数据量和失败摘要。
- 任务名称、详情、历史、编辑入口可继续承接后续排障和修复。
- 配置预览中应展示源端过滤条件，便于用户确认该任务不是全表同步。

**异常处理**

- 同名工作流已存在时走更新链路。
- 工作流上线失败时不应继续启动实例。
- 实例启动失败时保留错误信息和已保存工作流信息。

## 7. 数据与状态

### 7.0 同步任务资产状态

| 状态 | 说明 |
|------|------|
| DRAFT | 草稿，尚未发布为可运行工作流 |
| PUBLISHED | 已发布，当前配置已写入 Dolphin 工作流定义 |
| RUNNING | 最近实例运行中 |
| SUCCESS | 最近实例成功 |
| FAILED | 最近实例失败 |
| OFFLINE | 已下线，不参与调度 |
| WORKFLOW_MISSING | 对应 Dolphin 工作流定义缺失 |

### 7.1 页面核心状态

| 状态 | 说明 |
|------|------|
| project | 归属项目 |
| source | 源数据源、库、表、字段 |
| target | 目标数据源、库、Schema、表名 |
| selectedColumns | 已选源字段 |
| targetColumns | 目标字段定义 |
| mappings | 字段映射关系 |
| ddl | 目标端建表 SQL |
| generatedConfig | SeaTunnel 配置 |
| schedule | 周期调度配置 |
| workflow | 工作流定义信息 |
| runResult | 实例和同步结果 |
| asset | 同步任务资产信息，用于列表、详情和编辑回填 |
| runHistory | 同步任务运行历史摘要 |

### 7.2 状态一致性原则

- 字段勾选变化后，目标字段和默认映射同步变化。
- 目标字段变化后，DDL 和 SeaTunnel 配置同步变化。
- 映射变化后，DDL、SeaTunnel 配置、保存和运行都使用最新映射。
- 配置预览手动编辑后，需要明确标识当前配置是“已手工编辑”。
- 已有目标表场景下，如果用户手动把源字段连接到不同名目标字段，SeaTunnel 配置必须通过 `transform Sql` 生成目标字段名，sink 只读取 transform 输出，不能只依赖 source query 字段顺序或别名。
- SeaTunnel 配置中的 transform 查询字段顺序必须与目标字段区顺序一致，字段名必须与目标表字段一致。
- 已有目标表场景下，SeaTunnel JDBC sink 必须显式生成包含目标字段列表的 `insert into` 写入 SQL，字段顺序必须与 transform 输出顺序一致。

## 8. 权限与安全

- 页面不重复采集数据源密码。
- 数据源连接凭据由 DolphinScheduler 已有数据源体系管理。
- 同步任务保存和执行应遵守当前用户在项目、数据源、工作流上的权限。
- 错误信息中不得展示明文密码。

## 9. 非功能要求

| 类型 | 要求 |
|------|------|
| 可用性 | 主流程不要求用户理解 SeaTunnel 配置细节 |
| 性能 | 常见 100 字段以内表在字段设计步骤不卡顿 |
| 兼容性 | 不破坏 DolphinScheduler 原生菜单、工作流、定时、实例页面 |
| 可维护性 | 每次需求变更先改 ACP 文档，再开发，再点击测试 |
| 编码 | 中文注释、枚举、错误文案保持 UTF-8 |

## 10. 验收标准

### 10.1 P0 验收

- 能从菜单进入同步任务页面。
- MySQL 到 PostgreSQL 单表同步主流程跑通。
- Oracle 和 Doris 数据源可在同步任务中被选择。
- Oracle / Doris 作为源端时能读取库、表、字段元数据。
- Oracle / Doris 作为目标端时能生成合理 DDL，且确认建表不误报普通连接失败。
- 字段类型、注释、主键、可空正确展示。
- 字段选择和拖拽映射可用。
- DDL 可预览、可编辑、可确认执行。
- 保存同步任务成功。
- 保存后可在同步任务列表中找到该任务。
- 从同步任务列表可进入详情页。
- 从详情页可回到编辑向导并回填历史配置。
- 失败任务可看到失败摘要、最近实例和日志入口。
- 保存并执行成功触发实例。
- 执行提交成功后返回同步任务列表。
- 同步任务列表展示最近运行状态和同步数据量。

### 10.2 回归验收

- DolphinScheduler 原生定时弹框正常。
- 源中心正常。
- 项目管理正常。
- 运行实例详情正常。
