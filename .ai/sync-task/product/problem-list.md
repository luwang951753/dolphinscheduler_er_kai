# 同步任务需求问题清单

## 1. 文档定位

本文档用于记录“同步任务”模块为什么要做、要解决哪些问题、哪些问题已经确认、哪些问题仍需后续产品确认。

它不是页面说明书，也不是开发任务列表，而是后续维护时判断“这个功能该不该改、怎么改才不偏”的问题基线。

## 2. 核心用户问题

### P-001 用户不想手写 SeaTunnel 配置

**问题描述**

SeaTunnel 配置能力强，但直接暴露配置文件会让普通数据开发用户承担过多引擎细节。

**用户期望**

用户通过页面选择源端、目标端、字段和执行方式，系统自动生成配置。

**产品要求**

- 页面配置是主路径。
- SeaTunnel 配置预览是高级能力，不是主路径。
- 配置预览支持编辑，但编辑后必须仍能回到系统生成配置。

**验收点**

- 第 1-4 步可以不手写 SeaTunnel 配置完成同步任务。
- 配置预览内容来自当前页面状态，不是固定模板。

### P-002 用户需要在 DolphinScheduler 内完成同步闭环

**问题描述**

如果同步任务只是单独生成一个配置文件，用户仍需要手工创建工作流、上线、启动实例，体验割裂。

**用户期望**

同步任务保存后就是 DolphinScheduler 工作流；保存并执行后能直接看到实例状态。

**产品要求**

- 同步任务复用项目、工作流定义、工作流实例、定时调度能力。
- 不另建独立调度体系。
- 不破坏原生工作流页面。

**验收点**

- 保存同步任务能创建或更新工作流定义。
- 保存并执行能完成保存、上线、启动实例。
- 当前页能反馈执行状态和同步数据量。

### P-003 字段映射必须可理解、可调整、可回溯

**问题描述**

数据同步的核心风险是字段错配。简单下拉框或静态表格很难让用户快速确认源字段和目标字段关系。

**用户期望**

用户能看到源字段、目标字段和映射关系；默认自动映射，也能手动调整。

**产品要求**

- 源字段和目标字段左右分区。
- 默认按字段名一对一映射。
- 支持部分字段勾选。
- 支持拖拽连线调整映射。
- 映射变化必须影响 DDL、配置预览、保存和运行。

**验收点**

- 单选、全选、反选、清空都可用。
- 拖拽连线后目标字段来源立即变化。
- 调整映射后生成的配置使用最新映射。

### P-004 目标端建表不能偷偷执行

**问题描述**

如果页面选择字段后自动建表，用户难以判断目标端被改了什么，也无法提前检查 DDL。

**用户期望**

先看 DDL，再确认建表。

**产品要求**

- 生成建表语句只是预览。
- 只有点击“确认建表”才执行 DDL。
- DDL 可编辑。
- 表已存在、建表失败要给出明确反馈。

**验收点**

- 未点击确认建表前目标端不应新增表。
- 表已存在不应提示连接失败。

### P-005 执行结果必须在当前页给反馈

**问题描述**

保存并执行后如果页面无反馈或强制跳走，用户不知道任务是否提交成功，也不知道下一步看哪里。

**用户期望**

点击后当前页展示提交状态、实例状态、节点状态和同步数据量。

**产品要求**

- 当前页保留运行结果区。
- 可以提供实例详情入口，但不强制跳走。
- 成功态展示真实同步数据量。

**验收点**

- 保存并执行后页面展示实例 ID、状态、节点状态。
- 成功后展示来自日志或统计的同步数据量。

### P-006 页面不能要求重复输入数据源密码

**问题描述**

数据源已在源中心配置过连接信息，如果同步任务页面再次要求输入密码，会造成安全和体验问题。

**用户期望**

直接复用已有数据源连接。

**产品要求**

- 同步任务页面不展示源端或目标端密码输入。
- 后端和配置生成从数据源连接配置读取凭据。

**验收点**

- 页面没有密码输入项。
- 不出现“源端密码为空，请在页面补充”。

### P-007 二开不能破坏 DolphinScheduler 原生功能

**问题描述**

同步任务是 DolphinScheduler 二开模块，不是替代原生工作流。如果污染原生定时、工作流定义或菜单，会影响平台基本能力。

**用户期望**

新增能力自然融入 DolphinScheduler，原有功能照常可用。

**产品要求**

- 同步任务入口独立。
- 同步任务专用逻辑限制在同步任务页面和必要接口内。
- 定时弹框复用原生风格，但不能破坏原生入口。

**验收点**

- 原生工作流定义页“定时”正常。
- 项目管理、源中心、运行实例页正常。

## 3. 已确认产品决策

| 编号 | 决策 | 原因 |
|------|------|------|
| D-001 | 同步任务采用四步向导 | 降低一次性配置复杂度 |
| D-002 | SeaTunnel 是执行引擎，不是独立产品界面 | 用户目标是同步数据，不是学习引擎配置 |
| D-003 | 保存为 DolphinScheduler 工作流 | 复用平台调度、实例和权限体系 |
| D-004 | 字段映射采用左右字段区 + 中间连线 | 比单表格更直观表达映射 |
| D-005 | DDL 必须先预览后执行 | 避免目标库被隐式修改 |
| D-006 | 保存并执行后留在当前页展示状态 | 保持上下文，减少用户迷路 |
| D-007 | 周期调度参考原生定时弹框 | 降低学习成本，保护原生习惯 |

## 4. 历史问题回归清单

| 问题 | 必须规避的回归 |
|------|----------------|
| 字段类型显示 `unknown` | 字段元数据接口必须返回真实类型 |
| 中文注释乱码 | 元数据读取、传输、展示保持 UTF-8 |
| `enum('刑事','行政')` 解码异常 | 类型解析不能破坏原始字段类型 |
| `For input string: "NaN"` | 前端不能把无效项目或编码传给后端 |
| 表已存在误报连接失败 | 建表前识别目标表存在并给出友好提示 |
| 点击保存并执行无反馈 | 当前页必须展示状态 |
| 原生定时被破坏 | 同步任务定时逻辑不得污染原生弹框 |

## 5. 后续待确认问题

| 编号 | 问题 | 建议处理方式 |
|------|------|--------------|
| O-001 | 是否需要同步任务列表页 | 后续独立迭代，先不放进当前四步向导 |
| O-002 | 是否支持增量同步 | 后续按同步模式扩展，不和当前全量链路混在一起 |
