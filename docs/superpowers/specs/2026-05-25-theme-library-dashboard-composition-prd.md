# 主题库看板编排 PRD

日期：2026-05-25

## 1. 背景

前期曾尝试把“主题库 SQL 数据板块”扩展成独立大屏设计器，但该方向逐渐偏离当前目标：用户真正需要的是让主题库更灵活、更可用，而不是建设一个类似 DataV、FineReport、Tableau Dashboard Builder 的独立大屏平台。

因此，本 PRD 将产品方向收束为“主题库看板编排”。它不是通用大屏设计器，也不是完整 BI 平台，而是主题库内部的轻量能力，用来把某个分析场景下的多个 SQL 数据板块组织成可查看、可调整、可维护的场景看板。

核心目标是让主题库从“静态业务目录 + SQL 板块列表”升级为“围绕业务场景组织的数据分析页面”。

## 2. 产品定位

主题库看板编排是主题库模块的一部分，服务于主题域、业务对象、分析场景、SQL 数据板块这条主线。

它解决的问题是：

- 一个分析场景下可能有多个 SQL 数据板块，需要有组织地展示。
- 不同板块适合不同展示形式，例如指标卡、趋势图、排行榜、明细表。
- 技术人员需要维护 SQL、字段、数据口径。
- 业务人员希望不写 SQL，也能调整板块顺序、显隐、标题和展示形式。
- 主题库需要更像“可用的场景分析页”，而不是只是一组配置项。

它不解决的问题是：

- 不做独立大屏平台。
- 不做通用画布设计器。
- 不做任意组件市场。
- 不做复杂发布、分享、审批、运维体系。
- 不替代数据治理、数据质量、血缘和指标管理。

## 3. 用户角色

### 3.1 技术/数据人员

技术/数据人员负责数据配置和口径维护。

主要能力：

- 新增 SQL 数据板块。
- 选择已有数据集。
- 高级模式下手写 SQL。
- 试运行 SQL。
- 查看数据预览。
- 识别字段。
- 配置维度、指标、排序、过滤、展示列。
- 配置板块展示方式。
- 维护数据口径说明。

### 3.2 业务人员

业务人员负责看板展示和使用体验调整。

主要能力：

- 查看分析场景看板。
- 调整板块顺序。
- 设置板块显示或隐藏。
- 修改板块标题和说明。
- 切换板块展示方式。
- 调整板块宽度。

业务人员默认不具备 SQL 编辑权限。

## 4. 核心对象关系

```text
主题域
  -> 业务对象
    -> 分析场景
      -> 看板配置
        -> SQL 数据板块
```

说明：

- 一个主题域包含多个业务对象。
- 一个业务对象包含多个分析场景。
- 一个分析场景对应一个看板配置。
- 一个看板配置包含多个 SQL 数据板块。
- 看板配置只服务当前分析场景，不作为独立大屏资产发布。

## 5. 功能范围

### 5.1 分析场景看板

每个分析场景下展示一个看板区域。

看板区域包含：

- 场景名称。
- 场景说明。
- 分析路径。
- 重点结论。
- SQL 数据板块列表。
- 编辑入口。

查看模式下，用户只看到最终看板内容。

编辑模式下，用户可以调整板块配置。

### 5.2 SQL 数据板块

SQL 数据板块是看板编排的最小业务单元。

每个板块支持：

- 新增。
- 编辑。
- 复制。
- 删除。
- 启用/停用。
- 显示/隐藏。
- 上移/下移。
- 拖拽排序。
- 设置宽度。
- 设置展示方式。
- 配置数据来源。
- 配置字段映射。
- 配置标题、说明和口径备注。

### 5.3 轻量栅格编排

看板采用轻量栅格编排，不做自由画布。

板块宽度支持：

- `1/3`：适合小指标、提醒、短排行。
- `1/2`：适合趋势图、柱状图、小表格。
- `2/3`：适合主趋势图、组合分析板块。
- `整行`：适合明细表、长说明、复杂图表。

板块排列规则：

- 按排序顺序从左到右、从上到下自动排布。
- 宽度不足时自动换行。
- 整行板块独占一行。
- 隐藏板块不参与排布。

不支持：

- 自由拖拽坐标。
- 任意缩放像素尺寸。
- 旋转。
- 图层。
- 组件嵌套。
- 蓝图交互。

## 6. 数据来源

SQL 数据板块支持两种数据来源。

### 6.1 默认模式：选择已有数据集

默认模式面向业务人员和常规配置场景。

流程：

```text
选择已有数据集
  -> 读取字段
  -> 配置展示方式
  -> 配置字段映射
  -> 保存板块
```

能力：

- 选择当前主题库可用数据集。
- 展示数据集名称、来源、更新时间、负责人。
- 自动读取维度和指标字段。
- 支持数据预览。
- 支持字段映射。

### 6.2 高级模式：手写 SQL

高级模式面向技术/数据人员。

流程：

```text
选择数据源
  -> 编写 SQL
  -> 试运行
  -> 字段识别
  -> 数据预览
  -> 配置展示方式
  -> 保存板块
```

SQL 支持参数占位符：

```sql
${startDate}
${endDate}
${orgId}
${areaCode}
```

能力：

- 选择数据源。
- 编写 SQL。
- 试运行 SQL。
- 显示错误信息。
- 识别字段。
- 展示数据预览。
- 保存 SQL 配置。

边界：

- 本能力只保证当前板块能查询和展示。
- 不做完整 SQL 血缘。
- 不做指标治理。
- 不做质量规则。
- 不做跨模块数据治理。

## 7. 展示方式与字段配置

### 7.1 指标卡

适用场景：

- 总量。
- 比率。
- 同比/环比。
- 关键结果。

字段配置：

- 指标字段。
- 单位。
- 对比字段。
- 趋势字段。
- 标题字段，可选。

### 7.2 趋势图

适用场景：

- 时间趋势。
- 日/周/月变化。
- 多系列走势。

字段配置：

- 时间/维度字段。
- 指标字段。
- 系列字段，可选。
- 排序字段。
- 排序方向。

### 7.3 柱状图

适用场景：

- 分类对比。
- 区域对比。
- 单位对比。

字段配置：

- 分类字段。
- 指标字段。
- 排序字段。
- 排序方向。
- 最大条数。

### 7.4 饼图

适用场景：

- 占比分析。
- 分类构成。

字段配置：

- 分类字段。
- 数值字段。
- 最大分类数。
- 其他项合并，可选。

### 7.5 排行榜

适用场景：

- TopN。
- 责任单位排行。
- 热点对象排行。

字段配置：

- 名称字段。
- 数值字段。
- 排序方向。
- TopN 数量。

### 7.6 明细表

适用场景：

- 具体条目。
- 异常清单。
- 处置明细。

字段配置：

- 展示列。
- 列名。
- 排序字段。
- 排序方向。
- 最大行数。

### 7.7 文字说明

适用场景：

- 场景解释。
- 口径说明。
- 分析路径。

字段配置：

- 标题字段，可选。
- 内容字段。

### 7.8 提醒卡片

适用场景：

- 异常提示。
- 风险提醒。
- 待处理事项。

字段配置：

- 标题字段。
- 内容字段。
- 等级字段，可选。
- 时间字段，可选。

## 8. 页面交互

### 8.1 查看模式

查看模式是默认状态。

展示内容：

- 当前主题域。
- 当前业务对象。
- 当前分析场景。
- 场景说明。
- 场景看板。

隐藏内容：

- 排序控件。
- 删除按钮。
- 宽度设置。
- SQL 编辑入口，除非用户有技术权限。

### 8.2 编辑模式

有权限的用户可以进入编辑模式。

编辑模式能力：

- 新增 SQL 板块。
- 编辑板块。
- 复制板块。
- 删除板块。
- 拖拽排序。
- 设置宽度。
- 设置显示/隐藏。
- 切换展示方式。
- 保存配置。
- 取消编辑。

保存后，用户再次进入当前分析场景时，应恢复保存后的看板配置。

### 8.3 新增/编辑板块弹窗

弹窗建议分为四个区域：

1. 基础信息
   - 板块名称。
   - 板块说明。
   - 展示方式。
   - 宽度。
   - 显示状态。

2. 数据配置
   - 选择已有数据集。
   - 高级模式手写 SQL。
   - 参数提示。
   - 试运行。
   - 错误信息。

3. 字段配置
   - 根据展示方式动态展示字段表单。
   - 支持字段预览。

4. 预览确认
   - 展示板块渲染效果。
   - 展示预览数据。
   - 保存配置。

## 9. 权限原则

本 PRD 不设计完整权限平台，但需要保留最小权限边界。

权限分为：

- 查看看板。
- 编辑看板布局。
- 编辑 SQL 和数据源。
- 删除板块。

默认建议：

- 业务人员可以查看看板、调整展示方式、排序、显隐。
- 技术/数据人员可以编辑 SQL、数据源、字段映射。
- 删除板块需要更高权限或二次确认。

## 11. 保存与恢复

保存行为：

- 编辑模式点击保存后，保存当前分析场景的看板配置。
- 保存内容包括板块顺序、显隐、宽度、展示方式、数据来源、字段映射、标题说明。
- 保存后退出编辑模式。

恢复行为：

- 用户进入分析场景时，优先加载已保存的看板配置。
- 如果没有配置，则展示默认推荐布局。
- 如果某个 SQL 板块执行失败，板块显示错误状态，不影响其他板块渲染。

## 12. 错误与空状态

需要处理以下状态：

- 场景没有看板配置。
- 看板没有任何可见板块。
- SQL 执行失败。
- 数据集不存在。
- 字段映射失效。
- 查询结果为空。
- 用户无 SQL 编辑权限。

错误提示原则：

- 告诉用户哪里错了。
- 告诉用户能怎么修。
- 不把整个看板置为不可用。

## 13. 明确不做

为了避免再次偏成大屏设计器，本期明确不做：

- 不做独立大屏设计器。
- 不做通用组件市场。
- 不做自由画布拖拽。
- 不做像素级位置和尺寸。
- 不做图层面板。
- 不做组件嵌套。
- 不做蓝图交互。
- 不做发布/分享。
- 不做审批流。
- 不做访问统计。
- 不做权限治理平台。
- 不做数据治理/血缘/质量规则。
- 不做复杂主题皮肤市场。

## 14. 验收标准

功能验收：

- 一个分析场景下可以配置多个 SQL 数据板块。
- 板块可以选择已有数据集。
- 板块高级模式可以手写 SQL。
- SQL 可以试运行，并展示预览数据或错误信息。
- 字段识别后可以配置展示方式。
- 板块支持排序、显隐、宽度调整。
- 板块支持指标卡、趋势图、柱状图、饼图、排行榜、明细表、文字说明、提醒卡片。
- 保存后再次进入场景能恢复看板配置。
- 查看模式和编辑模式明确区分。

角色验收：

- 业务人员不需要理解大屏设计器，也能调整看板展示。
- 技术/数据人员可以完成 SQL、字段和口径配置。
- 无 SQL 权限用户不能编辑 SQL。

范围验收：

- 页面不出现“画布”“图层”“组件市场”“蓝图”“发布中心”等大屏设计器概念。
- 看板编排始终围绕主题库分析场景，不脱离主题库成为独立产品。

## 15. 后续建议

建议下一步先做产品原型，而不是直接二开：

1. 在现有主题库 SQL 数据板块原型基础上增加“编辑看板”模式。
2. 新增 SQL 板块弹窗按“基础信息、数据配置、字段配置、预览确认”组织。
3. 做轻量栅格布局效果，验证宽度、排序、显隐是否满足业务。
4. 原型确认后，再进入 DolphinScheduler 二开。
