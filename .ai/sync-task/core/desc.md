# 同步任务模块

## 模块职责

在 DolphinScheduler 菜单栏“源中心”右侧新增“同步任务”，提供类似 DataWorks 的数据同步配置页面。用户通过页面选择源数据源、目标数据源、库表字段、字段映射和执行方式，系统自动生成 SeaTunnel 配置并保存为 DolphinScheduler 工作流。

## 核心流程

1. 选择源与目标：确认项目、源数据源、源库、源表、目标数据源、目标库/Schema、目标表。
2. 设计字段：读取源字段元数据，勾选字段，设计目标字段类型、注释、主键、可空，必要时拖拽连线调整映射。
3. 执行与调度：预览建表 SQL，确认建表，配置立即执行或周期调度。
4. 预览与发布：查看/编辑 SeaTunnel 配置，保存同步任务，保存并执行，跳转运行实例或展示进度。

## 用户已明确的偏好

- 不要让用户手写 SeaTunnel 配置。
- 不要把全部功能平铺在一个页面。
- 不要在每一步重复放“查看配置预览”，应使用全局单一浮层。
- 第 1 步项目选择是必须项，需要必选标识。
- 第 4 步保存并执行后不能停在原页面让用户困惑，应跳转运行实例或展示进度。

## 当前重点

- 页面体验要接近成熟数据集成产品。
- 字段勾选、全选、反选、部分勾选必须都可用。
- 目标端建表 SQL 要友好展示，并允许用户修改。
- 工作流创建后应自动上线并启动实例。

## 维护文档入口

后续维护同步任务时，建议按以下顺序读取：

1. `product/problem-list.md`：先确认要解决的问题和历史决策。
2. `product/prd.md`：确认产品范围、页面结构、功能要求和验收标准。
3. `product/interaction-design.md`：确认页面交互细节和错误状态。
4. `backend-api/tech.md`：确认接口、数据流和后端契约。
5. `test/test-matrix.md`：确认本次改动需要覆盖哪些测试。
6. `../../quality/e2e-click-testing/test-cases.md`：执行详细真人点击测试用例。
