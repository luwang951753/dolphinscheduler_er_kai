# 同步任务 Agent 产品 PRD

## 1. 产品定位

同步任务 Agent 是“同步任务”模块的智能配置入口。它不是普通聊天窗口，而是一个可以把自然语言转为结构化同步任务配置的操作型 Agent。

Agent 的产品价值是降低配置门槛：非专业用户只描述“从哪里同步到哪里、同步多少、是否立即执行”，系统自动完成大部分向导配置；专业用户仍可以进入原向导审阅字段映射、源端过滤、数据去向和执行策略。

## 2. 页面入口

- 页面：`/sync-task`
- 位置：同步任务列表页右上角，与“新建同步任务”并列。
- 按钮文案：`Agent 创建同步任务`
- 打开方式：右侧抽屉，宽度约 560px。

## 3. 用户流程

1. 用户进入同步任务列表。
2. 点击 `Agent 创建同步任务`。
3. 输入自然语言命令。
4. 点击 `解析并生成方案`。
5. Agent 展示理解到的同步方向、匹配到的项目、源数据源、目标数据源、源表、目标表、字段数、过滤条件、执行意图和风险提示。
6. 用户点击：
   - `套用到向导`：进入第 2 步字段映射，可继续编辑。
   - `确认并执行`：先套用到向导，再复用现有保存并执行流程。

## 4. Agent 抽屉结构

### 4.1 命令输入区

- 输入框：多行文本，支持粘贴完整命令。
- 示例命令区：提供 2 条可点击示例。
- 自动执行开关：默认关闭；如果命令包含“立即执行”，解析后自动打开。

### 4.2 执行进度区

参考 DataWorks Copilot / Informatica Copilot 的“步骤解释”模式，展示 Agent 正在做什么：

1. 解析自然语言。
2. 匹配项目和数据源。
3. 加载库表元数据。
4. 生成字段映射。
5. 生成同步方案。

每一步有状态：等待、进行中、完成、失败。

### 4.3 方案卡片

方案卡片必须让用户快速判断 Agent 是否理解正确：

- 同步方向：`MYSQL -> POSTGRESQL`
- 源端：数据源、库、表。
- 目标端：数据源、库、Schema、目标表。
- 字段：源字段数、已映射字段数。
- 条件：抽样条数或源端过滤说明。
- 执行：立即执行 / 仅生成草稿。
- 置信度：高 / 中 / 低。

### 4.4 风险提示

风险提示不应吓人，但必须明确：

- 找不到目标表时会按源字段新建目标表。
- 未指定项目时使用第一个可用项目。
- 条数限制属于抽样同步，不代表生产增量策略。
- 字段类型不兼容时不会自动执行。

## 5. 与现有向导关系

Agent 不新建独立配置模型，必须复用现有同步任务向导状态：

- Agent 解析完成后写入现有 `state.source`、`state.target`、`state.fieldRows`、`state.sourceFilters`、`state.executionMode`。
- 字段映射仍使用现有 V4 双栏工作台。
- 保存和执行仍使用现有 `handleSaveWorkflow`、`handleRunWorkflow`。
- 列表和详情仍复用现有同步任务资产管理逻辑。

## 6. 验收标准

1. 从 `/sync-task` 列表页能打开 Agent 抽屉。
2. 输入示例命令后，Agent 能解析出源端、目标端、条数限制和执行意图。
3. Agent 能自动选择可用项目和匹配类型的数据源。
4. Agent 能加载源表字段并生成字段映射。
5. 点击 `套用到向导` 后，页面进入第 2 步，能看到字段映射双栏。
6. 点击 `确认并执行` 时，会触发现有保存并执行流程；若环境不满足，则必须给出明确错误。
7. 不得破坏原手工“新建同步任务”流程。

## 7. 后续增强

- Milvus 元数据向量索引：支持字段注释、历史任务、表用途语义召回。
- Agent 调度配置：从“每天凌晨 1 点同步”解析为 Dolphin 调度。
- Agent 诊断：任务失败后自然语言解释日志并给出修改建议。
