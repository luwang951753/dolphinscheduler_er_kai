# 同步任务模块测试用例基线文档

## 1. 文档定位

本文档用于沉淀 DolphinScheduler 二开“同步任务”模块的测试用例基线，作为后续每次开发、自测、回归和交付时必须参考的测试清单。

目标不是只记录“测一下流程”，而是把：

- 哪些功能必须测
- 哪些场景必须覆盖
- 哪些异常必须验证
- 哪些 Dolphin 原生功能必须回归
- 哪些结果必须截图、记录、说明

全部固化下来。

后续同步任务模块开发，应遵循以下顺序：

1. 先修改需求文档
2. 再修改测试用例文档
3. 再进入代码开发
4. 最后按本文档执行真实点击测试

## 2. 测试总体原则

### 2.1 核心原则

- 必须使用模拟人类逐步点击页面的方式测试。
- 不能只看代码。
- 不能只跑构建。
- 不能只跑接口。
- 不能只验证 Happy Path。
- 不能只验证同步任务自身，还必须验证未破坏 Dolphin 原生能力。

### 2.2 测试层次

每次交付前，至少需要执行以下四层测试：

1. 页面功能路径测试
2. 前后端接口链路测试
3. 异常与边界场景测试
4. 原生功能保护回归测试

### 2.3 测试记录要求

每次测试至少记录：

- 测试日期
- 测试人 / 执行主体
- 代码版本或本轮修改点
- 覆盖的测试用例编号
- 测试结果：通过 / 失败 / 阻塞
- 失败现象
- 修复后复测结果

### TC-P1-004 第 2 步字段映射影响 DDL 和配置生成

#### 目标

验证字段映射变更会同步影响后续结果。

#### 操作步骤

1. 在第 2 步调整映射关系
2. 进入第 3 步生成 DDL
3. 打开配置预览

#### 预期结果

- DDL 使用最新映射关系
- 配置预览使用最新映射关系
- 已有目标表手动连接异名字段后，SeaTunnel 配置必须包含 `transform { Sql { ... } }`
- `source` 通过 `result_table_name = "sync_source"` 输出临时表
- `transform` 通过 `source_table_name = "sync_source"` 读取源输出，并通过 `result_table_name = "sync_mapped"` 输出映射结果
- `transform` 查询必须按目标字段顺序生成 `源字段 as 目标字段`
- `sink` 必须通过 `source_table_name = "sync_mapped"` 读取转换后的结果
- `sink` 必须显式包含写入目标字段列表，例如 `query = "insert into public.a6 (id, ajbh, ajmc, ...) values (?, ?, ?, ...)"`
- sink query 的字段顺序必须与目标字段区和 transform 输出顺序一致
- 运行时使用 transform 输出写入目标表，不能直接把 source 输出写入 sink

### TC-P1-005 源端过滤条件影响配置生成

#### 目标

验证第 1 步配置的源端过滤条件会进入后续配置生成链路。

#### 操作步骤

1. 在第 1 步添加至少 2 条源端过滤条件
2. 进入第 4 步打开配置预览

- 配置中能看到源端过滤条件
- 条件语义与页面结构化配置一致
- 过滤条件只影响 source 读取范围，不改变目标表结构
- 预览中不会出现用户未配置的自由 SQL 片段

### TC-P1-006 目标字段属性修改生效

#### 目标

验证目标字段的类型、注释、主键、可空修改有效。

#### 操作步骤

- 配置预览中的目标字段定义与页面一致

- 目标字段区列顺序为：目标字段、目标类型、字段注释、主键、可空
- 目标字段是输入框
- 目标类型是下拉选择框
- 字段注释是输入框
- 主键、可空是逐行复选框
- 页面不出现重复“字段名”列
- 页面不出现“来自 xx”“当前来源”“映射方式”等冗余文案

### TC-P2-010 第 2 步字段映射 V4 锚点与图例

#### 目标

验证 V4 连线锚点、图例和线型符合设计。

#### 操作步骤

1. 进入第 2 步
2. 查看所有源字段和目标字段行
3. 查看已有自动映射线
4. 手动拖拽建立一条映射
5. 查看图例

#### 预期结果

- 所有源字段都有连接点，包括未映射字段
- 所有目标字段都有连接点，包括未映射字段
- 左右连接点样式一致
- 自动映射为虚线
- 手动拖拽映射为实线
- 页面展示“虚线：系统自动映射”“实线：手动拖拽映射”
- 连线左右端点与字段行垂直居中对齐

### TC-P2-011 第 2 步拖拽映射类型兼容校验

#### 目标

验证拖拽连线不会产生容易导致同步失败的字段类型映射。

#### 操作步骤

1. 在第 2 步找到一组兼容类型，例如 `INT -> BIGINT`
2. 拖拽建立映射
3. 找到一组不兼容类型，例如 `BIGINT -> INT` 或 `VARCHAR(255) -> VARCHAR(64)`
4. 拖拽建立映射

#### 预期结果

- 兼容类型可以建立连线
- 不兼容类型不能建立连线
- 不兼容时原映射不变化
- 页面提示源字段类型、目标字段类型和不允许映射的原因

### TC-P2-012 第 2 步目标字段名规则

#### 目标

验证目标字段名大小写规则真正作用到目标字段。

#### 操作步骤

1. 新建目标表模式进入第 2 步
2. 切换“保持源名”
3. 切换“全小写”
4. 切换“全大写”
5. 手工修改一个目标字段名
6. 再次切换“全小写”或“全大写”

#### 预期结果

- 保持源名时目标字段名与源字段名一致
- 全小写时目标字段输入框内容变为小写
- 全大写时目标字段输入框内容变为大写
- 手工修改过的目标字段名不被后续批量规则覆盖

### TC-P2-008 第 3 步 SQL 编辑器体验

#### 目标

验证 DDL 以专业 SQL 编辑器方式展示，而不是普通文本框。

#### 操作步骤

1. 完成第 2 步
2. 进入第 3 步
3. 等待 DDL 自动生成
4. 点击复制 SQL、格式化、重新生成
5. 手工编辑 SQL 后再次点击重新生成

#### 预期结果

- DDL 自动生成，不需要点击“生成建表语句”
- SQL 编辑器有语法高亮和行号
- 复制 SQL 可用
- 格式化可用
- 手工编辑后出现“已手工修改”状态
- 重新生成覆盖手工修改前有二次确认

## 13. 后续维护方式

后续如果你新增需求，不仅要改需求文档，也建议同步改本文档中的测试用例。

原则是：

- 新增一个功能点，就新增对应测试点
- 修复一个历史 bug，就沉淀对应回归用例
- 发现一个高频问题，就把它写成必测项

这样我后面每次开发，都能明确知道“这次必须测什么”，而不是临时拼测试路径。
