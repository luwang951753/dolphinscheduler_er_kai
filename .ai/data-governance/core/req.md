# 数据治理模块需求开发文档

## 1. 文档定位

本文档定义 DolphinScheduler 二开“数据治理”模块的第一版需求基线。数据治理第一版不集成 OpenMetadata、DataHub、Atlas 等外部系统，而是在 Dolphin 内部实现轻量治理工作台，借鉴 OpenMetadata 的核心产品能力和信息架构。

后续开发顺序必须遵循：

1. 更新需求与产品文档。
2. 制作并确认 HTML 产品原型。
3. 编写实施计划。
4. 进入真实 Dolphin 二开。
5. 使用模拟人类点击完成测试。

## 2. 产品定位

### 2.1 是什么

数据治理是 Dolphin 内置的轻量数据资产与质量治理模块，面向数据开发、平台管理员和数据负责人，帮助用户在一个入口中完成：

1. 查看数据资产目录。
2. 查看表和字段元数据。
3. 维护标签、责任人和业务说明。
4. 查看同步任务自动产生的表级血缘。
5. 配置基础数据质量规则。
6. 查看质量检测结果和治理问题。

### 2.2 不是什么

第一版不是完整 OpenMetadata 克隆，也不是独立元数据平台。

第一版不做：

- 独立采集器框架。
- Elasticsearch / Kafka / Airflow 等外部治理组件。
- 复杂全文搜索引擎。
- 复杂审批流和策略中心。
- 自动 PII 识别和复杂数据分类模型。
- 跨系统列级血缘全自动解析。
- 复杂数据地图和知识图谱。

## 3. 成熟产品参考

重点借鉴 OpenMetadata，但只吸收适合 Dolphin 内置化的核心能力：

| 产品 | 可借鉴能力 | 本模块取舍 |
|------|------------|------------|
| OpenMetadata | 资产目录、表详情、Owner、Tags、Glossary、Lineage、Data Quality、Activity | 借鉴信息架构和详情页，不引入其组件 |
| DataHub | 元数据搜索、Ownership、Lineage、Domain | 借鉴资产卡片和影响分析 |
| Collibra | 责任人、治理问题、业务术语 | 只做轻量责任人和问题闭环 |
| Microsoft Purview | 资产地图、分类、血缘 | 第一版只做资产目录和同步任务血缘 |
| DataWorks 数据治理 | 质量规则、问题告警、治理看板 | 质量规则和结果面板采用轻量实现 |

## 4. 第一版范围

### 4.1 必须覆盖

- Dolphin 菜单新增“数据治理”入口。
- 治理首页：资产数量、质量通过率、血缘关系数、待处理问题数。
- 数据资产目录：按数据源、数据库、表、标签、责任人、质量状态筛选。
- 表详情：基础信息、字段结构、标签、责任人、质量规则、血缘、最近同步任务。
- 血缘视图：先基于同步任务生成表级 `源表 -> 目标表` 关系。
- 数据质量：支持基础规则配置和最近检测结果展示。
- 治理问题：质量异常或人工创建问题，支持状态、责任人、备注。
- 从数据预览表详情、同步任务详情可跳转到对应治理资产。

### 4.2 第一版暂不覆盖

- 独立元数据采集调度。
- 列级血缘自动解析。
- 业务术语审批流。
- 标签审批流。
- 指标体系和 BI 语义层。
- 多租户隔离之外的复杂数据安全策略。

## 5. 数据来源

| 来源 | 产生的数据 |
|------|------------|
| 数据源中心 | 数据源类型、连接名称、权限边界 |
| 数据预览 | 数据库、表、字段、类型、注释、主键、可空 |
| 同步任务 | 源表、目标表、字段映射、执行状态、同步血缘 |
| 数据质量 | 质量规则、执行结果、异常数、问题单 |
| 人工维护 | 标签、责任人、业务说明、治理备注 |

数据预览模块只负责看数据、看表结构和发起治理跳转，不承载完整治理管理能力。数据预览中可以展示当前表的轻量质量状态和血缘入口，但点击后应进入数据治理模块的资产详情页，由数据治理统一展示质量规则、血缘和问题闭环。

## 6. 页面结构

第一版包含四类页面或视图：

1. 数据治理首页。
2. 数据资产目录。
3. 数据资产详情。
4. 质量与问题工作区。

页面可以先做成单页工作台，用顶部 Tab 切换，降低开发成本。

资产详情第一版不采用右侧窄栏展示。点击资产表格行后，应在当前表下方展开宽详情区，承载概览、字段、质量、血缘和问题 Tab，避免右侧详情面板过窄导致信息拥挤。

展开详情的顶部只保留资产识别信息，包括资产名、完整路径、质量状态、标签和编辑元数据入口。Owner、字段数、最近检测、最近同步等属性信息放入“概览”Tab，不在展开头部占用大块空间。

## 7. 核心对象

### 7.1 数据资产

数据资产的最小粒度为表，字段作为表详情的一部分展示。

字段：

- 资产 ID
- 数据源 ID / 名称 / 类型
- 数据库
- Schema
- 表名
- 表注释
- 字段数
- 标签
- 责任人
- 质量状态
- 最近同步任务
- 最近质量检测时间

### 7.2 字段元数据

- 字段名
- 字段类型
- 字段注释
- 主键
- 可空
- 敏感标签
- 质量规则数

### 7.3 血缘关系

第一版只要求表级血缘：

- 来源表
- 目标表
- 产生方式：同步任务
- 同步任务名称
- 最近运行状态
- 最近更新时间

### 7.4 质量规则

第一版支持：

- 非空校验
- 唯一性校验
- 数值范围
- 枚举值
- 正则表达式
- 自定义 SQL

质量规则必须区分字段级和表级：

- 字段级规则必须绑定检测字段，例如非空、唯一、范围、枚举、正则。
- 表级规则不强制绑定单个字段，例如自定义 SQL、跨字段一致性检查。
- 自定义 SQL 只允许查询类语句，必须返回 `abnormal_count` 字段，表示异常记录数。
- 规则保存前必须校验资产、字段或表级范围、失败阈值和规则参数完整性。
- 规则配置时必须展示系统生成的检测 SQL，让用户知道后续实际检测逻辑。
- 检测 SQL 必须拆分展示异常统计 SQL、异常样本 SQL、失败判定 SQL。
- 检测 SQL 必须支持用户手工编辑；用户编辑后 SQL 作为最终执行配置保存，规则条件变化不得静默覆盖用户修改，除非用户主动点击“重新生成 SQL”。
- 手工编辑后的检测 SQL 保存和试运行前仍需做基础校验：只允许查询类语句，必须返回 `abnormal_count`；非自定义 SQL 规则还应包含失败判定结果 `check_result`。
- 样本保存策略必须影响异常样本 SQL，例如保存前 50 条、保存前 200 条或仅保存数量。
- 检测范围必须影响异常统计 SQL 和异常样本 SQL；范围条件只有选择自定义 WHERE 时允许编辑。
- 失败阈值必须影响失败判定 SQL，而不是作为数据过滤条件写入 WHERE。
- 当前阶段不在质量规则创建时要求填写问题责任人；治理问题生成后再处理责任归属。
- 质量规则保存后必须绑定到当前资产，并展示在该资产详情的“质量”Tab 中。治理首页和资产目录只展示质量状态、异常数量等摘要，不作为规则编辑主入口。
- 保存草稿的规则展示为草稿状态，不参与自动检测；保存并启用的规则展示为待检测状态，可立即检测、查看历史结果、编辑和禁用。

质量规则必须包含执行策略：

- 检测范围：全表、最近 1 天、最近 7 天、自定义 WHERE。
- 失败阈值：异常行数大于 0、异常率大于 1%、异常率大于 5%、自定义阈值。
- 检测频率：随同步任务完成后检测、每天定时、每小时、手动执行。
- 问题策略：失败自动生成治理问题、连续失败升级严重程度、通过后是否自动关闭历史问题。

质量规则必须支持试运行：

- 试运行需要展示扫描行数、异常行数、异常率、预计结果。
- 试运行结果需要说明是否会生成治理问题。
- 试运行不应保存规则，也不应真实变更治理问题状态。

### 7.5 治理问题

- 问题标题
- 关联资产
- 问题类型
- 严重程度
- 责任人
- 状态：待处理、处理中、已解决、已忽略
- 最近备注

## 8. 交互要求

- 数据治理入口不能影响同步任务、数据预览和 Dolphin 原生工作流。
- 页面应是工具型后台，不做营销式大屏。
- 首页卡片必须能点击筛选资产或问题。
- 资产目录点击表行后，在该行下方展开资产详情，不跳转页面，也不使用右侧窄栏详情。
- 资产详情中的血缘节点可以点击进入关联资产。
- 血缘主视图归属数据治理模块。同步任务负责产生血缘，数据预览负责提供当前表血缘入口，数据治理负责展示、追踪和跳转上下游资产。
- 从同步任务详情进入治理资产时，应定位到对应源表或目标表。
- 从数据预览表结构进入治理资产时，应定位到当前表详情。
- 质量规则第一版可以先做页面配置和模拟结果；真实执行在实施阶段按后端能力拆分。

## 9. 验收标准

- 用户可以进入数据治理页面。
- 用户可以看到资产目录和资产详情。
- 用户可以看到表字段、标签、责任人、质量规则、血缘关系。
- 用户可以从同步任务血缘识别源表和目标表关系。
- 用户可以查看质量问题列表并切换状态。
- 页面无横向溢出，常见 1440 和 1920 宽度可完整操作。
