# 同步任务 Agent 测试用例

## TC-AGENT-P0-001 打开 Agent 抽屉

- 前置：登录 DolphinScheduler，进入 `/sync-task`。
- 步骤：
  1. 点击 `Agent 创建同步任务`。
  2. 观察右侧抽屉。
- 预期：
  - 抽屉打开。
  - 显示命令输入框、示例命令、解析按钮、进度区。

## TC-AGENT-P0-002 解析 MySQL 到 PostgreSQL 命令

- 命令：`把 mysql case_workbench.ajxx_tab 同步到 pg public.agent_ajxx_tab，只同步5条`
- 步骤：
  1. 输入命令。
  2. 点击 `解析并生成方案`。
- 预期：
  - 源类型为 `MYSQL`。
  - 源库表为 `case_workbench.ajxx_tab`。
  - 目标类型为 `POSTGRESQL`。
  - 目标 Schema 为 `public`。
  - 目标表为 `agent_ajxx_tab`。
  - 抽样限制为 `5`。

## TC-AGENT-P0-003 套用到向导

- 前置：TC-AGENT-P0-002 已生成方案。
- 步骤：
  1. 点击 `套用到向导`。
  2. 观察页面主区域。
- 预期：
  - 主页面进入同步任务向导。
  - 当前步骤为 `配置同步方案`。
  - 字段映射关系展示源字段区和目标字段设计区。
  - 新建目标表模式下，源字段默认全选并自动映射。

## TC-AGENT-P0-004 确认并执行

- 前置：本地 Dolphin 后端、SeaTunnel、MySQL、PostgreSQL 可用。
- 步骤：
  1. 输入包含“立即执行”的命令。
  2. 点击 `解析并生成方案`。
  3. 点击 `确认并执行`。
- 预期：
  - 触发现有保存工作流流程。
  - 工作流上线并启动实例。
  - 成功启动后返回同步任务列表。
  - 列表出现新任务或最新工作流记录。

## TC-AGENT-P1-001 低置信度命令

- 命令：`把案件数据同步到分析库`
- 预期：
  - Agent 不自动执行。
  - 展示缺失信息，例如源表、目标库、目标表不明确。
  - 引导用户补充命令或进入手工向导。

## TC-AGENT-P1-002 不破坏手工创建流程

- 步骤：
  1. 关闭 Agent 抽屉。
  2. 点击 `新建同步任务`。
  3. 正常手工选择项目、源端、目标端。
- 预期：
  - 原四步向导仍可使用。
  - 字段映射、过滤、数据去向、执行与调度功能不受影响。

## 本轮测试报告要求

开发完成后必须生成测试报告，至少包含：

- 前端类型检查结果。
- 浏览器模拟点击结果。
- Agent 解析结果截图或关键 DOM 文本。
- 已通过、未通过和跳过原因。
